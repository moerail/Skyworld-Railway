# SkyRail Suite 4.0.7：停车改道与调度撤销 MA

配套版本：**SkyTrainFolia 4.0.7、STCS 4.0.5、STA 2.1.3、SkyPCC 2.0.2**。单个 STF JAR 继续支持 Shiroha 26.2 和 26.3。

## 停车后由调度直接转岔

原有 MA 路径锁仍然有效。现在，若某道岔只被一列已停稳的手动列车 MA 预约，且道岔没有车身占用、位置不确定或其他冲突，调度员可以直接点“转换道岔”。司机不必先输入 release。

后台按顺序执行：

1. 标记道岔正在处理，暂停该列车的 MA 重算，保留旧预约。
2. 等待车端在列车运行 tick 中确认全列停稳、禁止牵引并清除旧车端授权。此阶段为 `WITHDRAWING_MA`。
3. 确认后释放前方 MA 预约，重新检查定位、停稳、占用、图版本和道岔状态，再执行转换。
4. 转换确认完成后重算原 MA 请求，结束临时停车保持。司机仍需正常操作手柄，不会自动加速。

如果确认期间列车移动、遥测过期、车体接近道岔、出现其他预约或转换失败，则拒绝或中止。失败后不自动恢复原进路请求；核实情况后重新申请 MA。多个 MA 持有者、自动列车以及未确认的停车状态不执行自动解锁。旧版 STF 没有车端确认接口时继续拒绝 MA 冲突。

`ma.lock-distance-meters` 仍默认 150 米，未通过缩小距离或取消占用检查来实现该功能。

## 撤销所选列车 MA → TR

- 网页 PCC：选择列车，在详情区点击“撤销 MA → TR”，核对目标并输入网页控制令牌确认。
- 支持手动列车在运行或停车状态下撤销。车端确认后进入 `TR`、禁止牵引并施加制动；不是只删服务端的 MA。
- 运行中撤销后，旧前方预约和道岔保护继续保留，直到确认全列停稳。车身占用不因撤销而清除。
- 无法联系车端、列车未加载或确认超时时，返回未确认／拒绝，不能将按钮点击成功当作列车已经制动。
- 司机恢复：停稳 → `/stcs ma ack` 进入 `PT` → `/stcs ma release` → 重新申请 MA。不能通过直接 demand 绕过调度停车保持。

调度员主动撤销在影子通道下也会执行 TR 停车保持；这与影子 MA 本身仅观察的日常行为不同。自动列车不在本次手动列控功能范围内，会被拒绝。

网页采用相同请求 ID 重试，服务端保留有限数量的请求结果以避免重复执行。网页继续要求开启控制功能和有效 Bearer token；STA Remote 接口使用 TLS 管理员鉴权及写请求限流。运行事件记录 `DISPATCHER_REVOKED` 和车端制动事件，保留时间、目标与来源。

## 升级

停服并备份后，同时替换已安装的四个插件为本页列出的版本，避免只升级按钮而缺少车端／STCS 接口。删除旧版本 JAR 后再放入新 JAR，保留插件配置、RailGraph、占用账本、证书和令牌。沿用原服务端启动方式。

网页强制刷新以加载新界面。本次 GitHub 发布仅包含四个服务端插件，Python 调度台更新及配置工具暂不发布。

## 验证与限制

本地最终构建：Shiroha 26.2、26.3 各 82 个 Java 测试入口通过；网页 294 个四语言词条检查、线路样式测试和桌面／移动尺寸浏览器测试通过。轨道图重建后的撤销保护和事件通知失败另在两版依赖下完成专项回归。

隔离测试覆盖停车改道的车端确认、确认前不解锁、确认期间移动拒绝、重复请求、主动 TR 在停车／运行两种状态下生效、过期请求拒绝、运行中保留预约及停稳后保留车身占用。网页浏览器测试覆盖实际按钮、鉴权头、固定请求 ID 轮询和令牌清除。

该版本尚需测试服实车验收，尤其是跨区域列车、密集站场、断线和转岔失败场景。测试时分别验证停车改道、运行中 revoke、停车 revoke、TR 恢复流程，核对道岔实际方向及占用账本；不要在未确认撤销结果时手工清除占用或强制转岔。
