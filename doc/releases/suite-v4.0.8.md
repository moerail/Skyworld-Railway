# SkyRail Suite 4.0.8 本地开发候选：TIMS 与两端驾驶席

版本：SkyTrainFolia 4.0.8、STCS 4.0.6、STA 2.1.4、SkyPCC 2.0.3。Python 调度台本地版本 2.1.4。**尚未发布到 GitHub，实机验收未完成。**单个 STF JAR 仍针对 Shiroha 26.2 和 26.3 隔离构建。

## 列车完整性

STF 保存独立、固定的车厢 UUID 清单，并在每次车端运动采样时检查全体成员、新鲜度（1 秒）、异步采样偏差（500 毫秒）及相邻车厢在已行轨道路径上的间隔。测量使用成员实体实际位置，并对不同采样时间做速度补偿；不根据运动目标位置推断。间距容差至少 1.25 格，并随编组间隔和采样时间差调整。单次轨道投影或跨区域采样抖动只在上一次完整性证据仍有效的短暂窗口内标为 `DEBOUNCING_*`，不会立即锁存停车；异常持续 750 毫秒或原有证据超过 1 秒则停车保持。缺失原车厢、重复身份或持续 1 秒的明显间隔异常标记 LOST。最初连续 1 秒新鲜检查通过后才能报告 COMPLETE。

确认后的 UNKNOWN／LOST 会切断牵引并保持制动。此前已确认完整的列车遇到故障进入 TR，随后恢复新鲜数据也不会自动清除保持。恢复时 `/st info` 显示 `AWAITING_ACK_<首次故障原因>`，首次原因写入列车存档，重启后仍可诊断。STCS 不再延长旧 MA，保留旧前方预约及车身占用；原先的进路请求需要重新申请。完整性不可信时不能用司机 release 出清保护。不同列车重复使用同一成员身份同样拒绝出清。PCC 和本地 Python 调度台显示 TIMS 状态、时间、故障车厢，STA 发布运行事件。

恢复：找回**同一 UUID、同一编组顺序**的车厢，确认沿轨道间隔恢复并让全列停稳，执行 `/st tims ack`。手动列车若模式为 TR，再执行 `/stcs ma ack`、`/stcs ma release`，最后重新申请 MA；自动列车需管理员明确重新 `/st start`。仅重新加载数据不能消除保持。既有 trains.yml 第一次升级时，以保存的成员清单作为基线并要求首次停稳人工确认；不要通过删账本或删车厢解除。

本实现是 Minecraft 内部的 TIMS 模拟，不构成现实铁路的安全认证，也不声称符合 ETCS／IEC 通信协议。版本未覆盖在运行中解编、并编或列车重新编号；需先按安全停车与重新建立列车的流程处理编组变更。

## 驾驶席与位置

`/st drive` 仅允许坐在编组第一个或最后一个车厢的乘客。接管时换向器回中立；`forward` 表示从**当前驾驶端向外**，`backward` 表示向另一端。hotbar 右击换向器按“前进 → 中立 → 后退 → 中立 → 前进”循环；手动执行 forward/backward 后，下一个中立档仍会转向另一档。玩家视角转动不影响方向；换到另一端必须释放并重新申请驾驶权。

`/st info <列车名>` 报告行驶端最后观测到的世界坐标与 UTC 时间；观测过期或完整性不确定时明确标为“最后报告”，不伪称当前位置。

## 编号彩蛋

STA 的私有 TIMS 状态带 `messageId=1136`（沿用本项目对 ETCS Message 136 的加 1000 编号）和 `packetId=1000`（致意 ETCS 位置报告 Packet 0）。ERA 发布的 [UNISIG Hazard Log](https://www.era.europa.eu/system/files/2022-11/subset_113_1.pdf) 确认 Position Report Packet 0／1 有 `Q_LENGTH`、`L_TRAININT` 等完整性信息。IEC 的 [61375-1](https://webstore.iec.ch/en/publication/72350) 是列车通信网络架构标准，未在本功能中冒用其报文号。上述数字仅为 SkyRail 私有 JSON 元数据，并非真实 ETCS 编码。

### 2026-10-03 V_target 巡航限速修正

原先伪 ATO 进入车站 `APPROACH` 阶段时，将驾驶目标改为车辆最高速度；即使此前 `V_target=0.5`，目标上跳也会重置保速状态并重新触发 P4。现在接近阶段使用受 `V_target` 限制的巡航目标；站牌显式速度只能降低当前 `V_target`，不能抬高它。车辆运动计算对自动驾驶再次应用该上限，包含动力轨加速后的结果。抵达目标附近仍由中立／P1 保速，超速时原有常用制动逻辑继续工作。新增固定 0.5 格/tick、站牌速度 1.0 格/tick 的回归场景，验证多次档位切换不请求 P4。
