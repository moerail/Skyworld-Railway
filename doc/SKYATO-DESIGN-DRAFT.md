# SkyATO 设计草案：图驱动正线运行与车库牌子

状态：讨论稿，本文命令、配置与接口均尚未实现。

## 1. 目标与边界

- 正线按 RailGraph 和运行计划自动行驶，不要求沿线布置自动驾驶牌子。
- 车库允许使用实体牌子处理入库、出库和编组归属。
- SkyATO 负责运行任务、停站与速度目标；STCS 负责可执行 MA、占用、进路和道岔确认；STF 负责列车实体、牵引和制动；SkyPCC 负责显示、调度与人工干预。
- 线路目标或调度批准不是 MA。SkyATO 只能在已确认、当前有效的 MA 内牵引。数据未知、过期或冲突时保持停车。
- 第一阶段只在隔离测试线运行；自动列车接入可执行保护通道、M3 实服验收和实体丢失事故复盘完成后，才能讨论正线无人值守放行。

## 2. 车库牌子

```text
[skyato]
depot
<车库名称>
```

管理员放置后，SkyATO 将牌子所在轨道注册为车库基点，并沿轨道两个方向读取 RailGraph，显示左右可用停车长度、可划分的停车位与适配某列车长度后的容量。方向以牌子的朝向固定，并在反馈中显示对应的轨道端点；不能仅用玩家视角定义左右。

容量计算是规划结果，不是空闲证明。扫描到图缺口、未知道岔、交叉、站台或轨道尽头就停止；未确认的轨道部分标为未知。每个停车位记录固定的 edge + offset 区间、允许方向、最大编组长度和缓冲距离。实际分配还要检查占用、预约、道岔与列车完整观测。一个物理停车位只允许一列车持有。

牌子是车库入口和管理员操作点；站台与正线停点使用虚拟 RailGraph 标记。删除牌子时，已有车库及停车位应先进入维护状态；有列车归属或占用时拒绝直接删除其数据。

每列车可保存 `homeDepotId`（默认归属车库）和可选 `homeBerthId`（默认停车位）。手动列车也能保存这两个属性，但它们不改变手动驾驶、MA 或制动；自动列车可把它们作为结束任务后的回库目标。归属不等于实时停放位置。

## 3. 线路与路径点

区分两个概念：

- **RailGraph 基础线路**：物理拓扑、方向、道岔和边的归属。
- **SkyATO 运营线路**：有序路径点、停站规则、折返和循环规则，可跨多个基础线路。命令中的 `<线路名>` 指运营线路。

路径点以稳定设备 UUID 指向现有 RailGraph 节点；无需实体牌子的地点使用虚拟节点，持久化为 `graphRevision + edgeId + offsetMeters + direction`，并有独立 UUID。虚拟节点可由管理员在轨道上选点或在 SkyPCC 地图上创建。图重建后若无法唯一重新匹配，线路变为 `NEEDS_REVIEW`，不得自动运行。

每个路径点至少有 `PASS`、`STOP`、`TURNBACK`、`DEPOT` 类型；`STOP` 带停车偏移、停站时长、适用行车方向与站台长度。路线需预先验证连续、方向、道岔转换、列车长度和折返条件。循环一次定义为执行完整的有序路径并回到指定起点；往返线路必须显式定义返程或折返，单向终到线路不能隐式无限循环。

## 4. 管理员指令与编辑玩法

对玩家保留简短的 `/skyato create <线路名>` 与 `/skyato <线路名> ...` 形式。线路名不得与 `create`、`assign`、`stop`、`resume`、`unassign`、`status`、`depot` 等保留字冲突；内部命令处理器仍按明确的子命令分派。

| 指令 | 含义 |
| --- | --- |
| `/skyato depot info <车库>` | 查看左右长度、停车位、归属列车与实时占用 |
| `/skyato depot home <列车> <车库> [停车位]` | 设置默认归属；手动列车仅存元数据 |
| `/skyato create <线路名>` | 创建空运营线路 |
| `/skyato <线路名> edit` | 进入路径点编辑模式；空手右键现有线路设备牌子可追加 UUID |
| `/skyato <线路名> add <设备UUID> [pass|stop|turnback]` | 直接追加已有设备 |
| `/skyato <线路名> add here [pass|stop|turnback]` | 在脚下或选中的轨道位置创建虚拟路径点 |
| `/skyato <线路名> remove <序号|UUID>` | 从线路移除路径点，不删除 RailGraph 设备 |
| `/skyato <线路名> list` | 显示顺序、方向、类型与停站参数 |
| `/skyato <线路名> set <序号> <字段> <值>` | 修改停站、方向、折返等参数 |
| `/skyato <线路名> validate` | 检查可达性、方向、停车长度与图版本；不申请 MA |
| `/skyato <线路名> preview` | 在 SkyPCC 高亮实际路径和待开通道岔 |
| `/skyato <线路名> publish` | 将验证通过的草稿发布为可派车版本 |
| `/skyato <线路名> cancel` | 退出编辑模式，放弃未提交编辑 |
| `/skyato assign <列车> <线路名> [循环次数]` | 派车；省略次数表示无限循环，仅接受闭合或显式往返线路 |
| `/skyato stop <列车>` | 计划性常用制动，在最近的可安全停车点停稳并累计运营等待时间 |
| `/skyato resume <列车>` | 重新检查列车、线路、道岔与 MA 后继续任务 |
| `/skyato unassign <列车> [return|hold]` | 撤销后续循环，回库或停稳保持 |
| `/skyato status <列车>` | 查看任务、下一点、当前 MA、等待原因与累计等待时间 |

编辑模式应只接受该管理员对当前线路的操作，设超时与 `cancel`。右键现有设备牌子时显示 UUID 和候选方向，管理员确认后才追加；普通右键不能直接改动设备。对虚拟站点提供 `add here`，这样正线无需放牌。线路编辑使用草稿版本，不改变正在执行的列车任务；发布后新任务使用新版本，已有任务继续旧版本或在安全停车后显式迁移。

## 5. 派车与运行状态

`assign` 先检查列车实体和全部成员已加载且观测新鲜、列车停稳、无人工驾驶占用、编组长度适配、所在图位置可定位、运营线路已发布且可达、图版本一致。只有保存的编组名单而找不到矿车实体时必须拒绝派车。可达性仅说明存在拓扑路径，不授予行车许可。

运行状态建议为：`IDLE -> VALIDATING -> WAIT_ROUTE -> WAIT_MA -> DEPART -> CRUISE -> APPROACH -> DWELL -> TURNBACK/RETURN -> COMPLETE`，另有 `SERVICE_HOLD`、`RECOVERING`、`FAULT`。每次状态转换记录原因、任务版本、图版本与 MA 身份。

SkyATO 向服务器端进路服务提交预期路径。STCS 校验占用与冲突，申请道岔转换，并等待**物理状态确认和锁闭**后才给可执行 MA。SkyPCC 显示自动请求与允许人工批准/拒绝，不由网页前端直接决定安全状态。道岔返回 `UNCONFIRMED`、图缺口、占用未知或 MA 不可用时保持 `WAIT_ROUTE`/`WAIT_MA`；不能按命令已发送就发车。当前 4.0.2 仍有道岔实际写入后返回 `UNCONFIRMED` 的已知限制，需要单独修复和验收。

车载目标速度取线路限速、停车曲线、当前 MA 的 EoA/速度限制中最严格者。ATO 输出牵引/惰行/常用制动请求；独立 ATP 可覆盖该请求并实施更强制动。任何定位或许可失效都停止牵引，按保留的最后有效边界减速；无法保证边界时保持制动或进入故障处理。

`stop` 是服务性停车请求，不等同紧急制动或撤销任务。系统选择当前 MA 内最近可安全停车处，以常用制动停稳，记录 `holdStartedAt` 和累计等待时间。若剩余距离不足以常用制动停车，保护层按需要介入。`resume` 必须重新取得当前有效 MA；等待时间只记入运营统计，不改变占用时效或 MA 安全判断。紧急情况仍由独立 EB/Trip 流程处理。

## 6. 分阶段实现

1. **模型与编辑器**：运营线路、车库、停车位、虚拟路径点、版本化持久化、命令编辑与 SkyPCC 预览；不控车。
2. **单列车隔离测试**：在独立试验线完成拓扑规划、精确停站、`stop/resume`、折返；先观察驾驶建议，再接入实体执行器。
3. **保护闭环**：为自动列车建立受约束的任务身份和可执行 MA 通道，完成道岔确认、MA 身份与撤销、实体/定位缺失时的保持行为。不能复用玩家驾驶租约而不定义自动任务所有权。
4. **多列车运营**：冲突排路、停车位分配、时刻表与延误恢复；在实体丢失、区块卸载、重启、图重建和通信故障注入下验收。

当前节点通过完整度监视器仍只读，不可据此自动释放占用。首版 SkyATO 不依赖完整度推断放行；前方占用未知则等待。自动释放和更高密度运行应在列车完整性证据链成熟后另行设计。
