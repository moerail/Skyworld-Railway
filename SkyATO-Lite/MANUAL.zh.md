## 1. SAL 做什么

SkyATO-Lite（简称 SAL）提供预设线路的按钮叫车、出入库、停站、折返、巡航速度控制和乘客屏幕信息。

一次正常任务的流程是：

```text
按钮叫车
  → 等待批次匹配：在允许的共享车池中选择可达本次始发点的列车
  → 必要时停稳换向，申请进路与 MA
  → 前往第一站并等待乘客
  → 按发布的线路顺序运行、停站
  → 末站停站
  → 选择可达且容纳得下整列车的库位
  → 中心停车，结束任务，进入自动待命
```

运营线路与 STCS 的工务线路不是同一个概念：

| 名称 | 用途 | 示例 |
| --- | --- | --- |
| STCS 工务线路 | 轨道归属、里程和工务设备 | `main:up` |
| SAL 运营线路 | 有序访问的站点、设备和折返安排 | `Line1` |
| 车辆段 | 列车归属和叫车来源 | `maintown` |
| 停车位 | 车辆段中的独立存车位置 | `maintown/L1` |

SAL 从 RailGraph 寻路；STCS 负责占用、排路、道岔锁闭和 MA；STF 通过 STA 契约执行列车实体操作。绿色预览、空库位和成功叫车都不等于已经获准移动。

## 2. 安装、权限与升级

### 2.1 安装顺序

1. 正常停服，备份世界和插件数据。
2. 安装配套的 STA、STF、STCS、SAL；需要网页操作时加入配套 PCC。
3. 合并配置并启动服务器。
4. 先完成 STCS 的设备登记和 RailGraph 建图，再设置 SAL 设备。
5. 先用一列短编组验收，再增加车长、列数和库位。

保留列车、RailGraph、占用账本、SAL 状态和线路发布数据。升级不需要清空账本。

### 2.2 权限

| 权限 | 默认 | 用途 |
| --- | --- | --- |
| `skyatolite.driver` | 所有玩家 | 查看普通帮助、释放待命自动车、确认库位纳管 |
| `skyatolite.admin` | OP | 登记或拆除 SAL 牌子、编辑线路、绑定归属、管理员叫车及任务管理 |
| `skytrain.use` | 由 STF 权限配置决定 | SAL 驾驶权移交同时要求此权限；手动驾驶还需满足 STF 的检查 |

普通玩家使用已配置的叫车按钮，不需要执行管理员的 `/sal awake` 指令。SAL 命令前缀为蓝色 `[SkyATO-Lite]`；`/skyatol` 是 `/sal` 的别名。

### 2.3 从旧版升级时先看这里

- **depot 已改成中心停车。** 旧版按车头对牌摆放的列车，需要手动重新居中；系统不会自动挪动车辆。
- STF 的旧自动牌和 `mode auto`／`mode automatic` 已移除。自动运营使用 SAL，不能靠旧指令恢复。
- 新驾驶会话取得驾驶权后先等待选择方向；选定前进或后退才默认申请 FS，并等待有效 MA；不能把“默认 FS”理解为无条件放行。
- 新线GLOBAL：停车组仅作可选偏好；RESTRICTED模式必须至少指定一个允许组。旧线保持RESTRICTED。
- 草稿与发布版分开，已有任务固定使用自己的发布版本。
- 服务器重启取消未承诺叫车请求；未结束任务进入恢复保持，不会自行重新发车。

## 3. 玩家乘车

1. 在站台按对应线路的叫车按钮。
2. 等列车到达、停稳，再上车。
3. 列车按站停时间发车；途中可能在屏幕中央显示沿线提示。
4. 到目的地自行下车。

一次叫车执行一次已配置的循环任务；不会因为还有乘客而自动无限续圈，也不会因为最后一名乘客下车就立刻另找捷径回库。无人上车仍会完成这次任务。乘客可以跟车回库，但下一圈要重新叫车。

如果同一发布版、同一始发访问的任务车仍停在首站且满足复用条件，重新叫车会复用它：取消回库安排，必要时安全换向，重新计算首站站停时间。已经离开首站或处于故障状态的车辆不按此规则复用。

## 4. 告示牌逐行填写

### 4.1 通用规则

牌头 `[SAL]` 和 `[SkyATOL]` 等价，以下统一使用 `[SAL]`。

- 登记、修改和拆除牌子需要管理员权限。
- 除 `awake` 外，牌子应放在对应轨道柱下：站立牌需要支撑，墙牌附着在相应轨道柱上。
- 对应轨道必须已在 STCS RailGraph 中；SAL 不自行加载区块扫描铁轨。
- 车辆段、停车位、线路名称可使用文字、数字、下划线、短横线，最长 64 字符；不要使用空格、斜杠或冒号。
- `maintown/L1` 是系统组合出的库位标识。牌子上应将 `maintown`、`L1` 分别写在第三、第四行。
- 被运行任务引用的设备可能拒绝拆改；先处理任务，不能强拆后要求列车继续运行。

### 4.2 depot：车辆段停车位

```text
[SAL]
depot
maintown
L1
```

| 行 | 含义 |
| --- | --- |
| 第一行 | SAL 牌头 |
| 第二行 | `depot` |
| 第三行 | 车辆段名 |
| 第四行 | 该车辆段内唯一的停车位名 |

另一个停车位写为：

```text
[SAL]
depot
maintown
L2
```

同一股道可以设置多个 depot。牌子是首选列车中心；最终停车中心可能在本库位范围内调整，详见第 7 节。

### 4.3 station：公共停车点

```text
[SAL]
station
15
MainStart
```

第三行是默认站停秒数，支持小数，范围0–3600；第四行是全局唯一停车点名称，不绑定线路。先登记station，再在PCC或指令里明确加入访问，放牌不自动追加草稿。同一停车点可服务多条线路，每次访问可单独覆盖停站和折返。名称只用文字、数字、下划线、短横线，最长64字符。

station仍按既有停车语义执行，本轮只把名称与线路解耦，没有把station改成depot中心停车。

### 4.4 awake：线路＋始发点叫车

```text
[SAL]
awake
MainTour
MainStart
```

第三行是已发布且未停用的运营线路，第四行是该发布版中的公共station名称。用按钮给牌或支撑方块供电，不要求放在轨道下。初次电平只初始化，真实上升沿触发，重复请求有约2秒防连点并合并接客。

管理员同义指令：

```text
/sal awake MainTour MainStart
```

如果同一站在环线中有多个独立访问，第四行改为PCC复制出的 `MainStart@实际访问UUID`，命令也接受这个引用。末尾重复首站只作闭环别名，不是另一个始发入口。访问UUID在重排后保持稳定；不要自行编造。

在B叫车会将A→B→C→A旋转为B→C→A→B；必要时迎车到站后先停稳换向再计算始发站停，完成一圈后回库。具有特殊终到覆盖的闭环别名不作为独立始发；需要不同终到处理时另建服务定义。

### 4.5 property：巡航速度

```text
[SAL]
property
V_target
36km/h
```

也可以使用简写，第四行留空：

```text
[SAL]
v_target
36km/h

```

支持 `km/h`、`kmh`、`m/s`、`m/t`、`b/t`、`mph`；无单位按方块/tick 解释。建议明确写单位，避免把 `36` 当成 `36km/h`。

`property` 目前只接受 `V_target`。它修改本次任务的巡航目标，仍受车型限速、MA 和 ATP 约束；不是越过红灯或解除制动的指令。

### 4.6 message：乘客中央提示

```text
[SAL]
message
欢迎来到 Skyworld
5
```

第三行是文本，第四行是显示秒数，须大于 0 且不超过 3600 秒。

文字通过屏幕中央 Title 显示给本车乘客。遇到新 message 立即覆盖旧 message，不排队；文本不执行指令。

## 5. 从零建立一条环线

1. 先完成STCS RailGraph登记，确认设备与存车股道边界。depot牌保留原停车组/库位，先放公共MainStart、Scenic两处station，不需要先有线路。
2. 面向首站计划发车方向：`/sal route create MainTour`。可选加偏好组 `maintown`；无组也允许创建GLOBAL草稿。
3. 设方向 `/sal route direction MainTour east`，可选north/south/east/west。
4. 在首站旁 `/sal route bind MainTour`，有多个8格内设备时 `/sal route choose 2`。选择60秒有效，图/草稿改变可使其失效。也可传真实设备UUID或station完整ID。
5. 按行车顺序绑定中间应答器、道岔、Scenic，最后再绑定MainStart形成闭环。不必逐个选择相邻应答器，默认自动取最短合法路径；要指定其它走法时补中间访问或有向图边。不能按当前道岔开向猜路线。
6. station访问命令末加reverse可设此次停站后折返；这不是任意位置自动多次折返寻路。
7. 设置供车策略，核对、验证、发布：

```text
/sal route supply MainTour global 30 120
/sal route depot MainTour maintown
/sal route list MainTour
/sal route preview MainTour
/sal route validate MainTour
/sal route publish MainTour
```

30是非偏好车组罚秒，120是单车迎车估计上限；没有偏好组可用 `/sal route depot MainTour none`。仅允许选中组时用restricted且至少保留一组。初次长线路可将迎车上限设为300，确认实际时间后再调。

`/sal route remove MainTour 3`删除第三次访问；`preview MainTour off`关个人粒子。红色/虚线说明路径未成立，绿色只说明图验证，不等于取得MA或区段空闲。

游戏修改会保存草稿，无单独route save命令；成功publish关闭本侧编辑会话，也可 `/sal route close MainTour`。切换PCC前先关闭游戏编辑。同线并发冻结后需 `/sal route resolve MainTour DISCARD` 或选actor人工处理；解消本身不发布。

发布后放awake按钮，或 `/sal awake MainTour MainStart`。未发布草稿不会用于叫车，运行中任务也不会被新发布替换。

### 共享派车怎样选车

默认500毫秒收集一批请求，先复用/合并已有同版同入口接客，再对可行车进行最大数量、最小成本匹配。硬门槛包括SAL待命、无真人驾驶权/其他任务、完整新鲜车身观测、可达路径、空间与障碍。GLOBAL搜索所有登记组，RESTRICTED只搜索允许组。

成本为估计迎车秒数＋非偏好组罚秒＋可选末车库存罚秒；等待时间参与优先权。迎车估计采用路径距离/默认巡航，加2秒准备和每次换端8秒，不是精确行程保证。队列最多64、单批候选最多256、计算预算500毫秒，不保证预算内穷尽所有路径。

SAL-dispatch-compute是独立JVM后台线程，仅计算不变快照。主协调器提交前复核版本、时效、位置、方向、编组、归属、驾驶权，随后才确认占车并经STA交由STCS/STF执行。计算超过5秒的结果废弃，不能把建议当MA。

请求默认120秒未匹配会显示超时原因，PCC和 /sal status 可观察。已分配任务不会因为后来出现更便宜的车就随意换车。GLOBAL完成任务可入任意合适组并更新home；RESTRICTED仍受组限制。单端股道深位优先和全车空间判定继续执行。

## 6. 登记列车并准备发车

### 6.1 先创建 STF 编组

列车必须是已创建的 STF 编组，不是几辆互不关联的矿车。创建和手动驾驶参考 [STF 中文驾驶说明](../Common/doc/driver/README.zh.md)。

### 6.2 绑定车辆段归属

管理员坐入列车，执行：

```text
/sal train home maintown
```

查询归属：

```text
/sal train home
```

绑定的是车辆段，不是 `L1` 这个固定停车位；不会立即发车或把车传送入库。当前有任务时不能直接改归属。

### 6.3 将列车停到合法库位

没有手动驾驶员且未被明确保留为手动状态的归属列车，可以手推到合法 depot 中心目标附近，由系统捕获并保持停车。

已有手动驾驶权，或已经释放为手动待命的车，使用第 8 节的显式纳管流程。不能靠离车或直接 `/st release` 表示同意自动接管。

可发车车辆需要观测新鲜、车厢完整、无 TIMS 保持、没有其他任务或手动司机，并且存在不被其他列车挡住的合法首站路径。朝向反了可以在满足条件后自动换向，不必预先人工摆正。

### 6.4 首次叫车

放置 awake 按钮，或管理员先执行：

```text
/sal awake MainTour MainStart
/sal status
```

如果没有合适车辆或路径，系统拒绝叫车，不会自动生成新列车。列车已经出库后，MA、区块准备或道岔确认仍可能使它停车等待。

## 7. 中心停车与多个库位

### 7.1 默认规则

depot 牌代表首选停车中心。系统沿 RailGraph 计算库位两侧空间，必要时在本库位内部调整计划中心，让整列车都在有效边界内。

| 情况 | 处理 |
| --- | --- |
| 中心正对牌即可容纳整车 | 正常中心停车 |
| 牌子偏向一端，另一侧空间足够 | 向内调整到最近的合法中心 |
| 该库位放不下整列车 | 排除此位，尝试其他可达库位 |
| 所有合适位置都被占、被预约或不可达 | 保持等待 |
| 边界或列车位置无法确认 | 不按空闲库位分配 |

系统不会越界借用相邻库位，也不会为了腾位自动移动其他列车。

### 7.2 同股道多个库位

相邻停车点之间按沿轨距离取中点划分空间，再留出配置的净间隔。不同车辆段名下的相邻 depot 也要互相避让。

```text
出入口 ── 库位A ── 净间隔 ── 库位B ── 出入口或END
```

曲线长度按沿轨距离计算；道岔和尽头另留安全余量。普通应答器不会自动把同一存车股道拆成不同股道。

### 7.3 单端与双端

- **单端股道**：一端为道岔，另一端为 END。同股道优先使用深处的可达库位；出库排除被靠出口车辆挡住的车。
- **双端股道**：两端为道岔。评估两个方向的合法路径，选择可达的较短方案。
- **ORIGIN 边界**：只代表已观测图边界，不等于物理尽头；不能据此确认库位容量。

几何空间够用，仍须由 STCS 批准实际进路和 MA。双端识别不代表已实现额外的“A端只进、B端只出”配置。

### 7.4 在 PCC 确认容量

选择车辆段后，查看库位的最大车长、单端／双端类型和不可用原因。地图显示库位范围；有回库目标的任务还显示计划中心和偏移。

建议先查看容量，再安排编组长度。旧车头对牌的存车需要手动调整，不能把“有车靠近 depot”当作已正确入位。

## 8. 手动驾驶与自动驾驶移交

### 8.1 自动待命车改为手动

适用于已经回库、停稳且没有运行任务的自动待命车：

1. 坐入列车。
2. 执行 `/sal release`。
3. 等待待命释放完成，列车保持制动。
4. 到适合驾驶的首／末车厢执行 `/st drive`，按 STF 流程驾驶。

```text
/sal release
/st drive
```

两步之间应等待反馈，不要把它当成必须瞬间连发的宏。`/sal release` 不接收列车 UUID，也不能用于夺取正在运行的 SAL 任务。

### 8.2 手动车交给 SAL

1. 保持当前手动驾驶权，让列车车身任意一部分覆盖 depot 停车点，并停稳。手动纳管不要求中心对牌，也不要求满足自动回库的精确停车位置。
2. 速度为零并连续停稳 3 秒。
3. 停稳 3 秒会给出随机六位确认码；也可停稳后直接执行 `/sal handover` 立即申请，不必等 3 秒。点击 **确认 SAL 纳管**，或执行 `/sal handover 六位确认码`。
4. 再输入 `/st release`，或点击第二个释放驾驶权按钮。
5. 等待“移管完成”的反馈。

例如收到 `483921`，输入 `/sal handover 483921`；这个数字只是示例，必须使用本次收到的随机六位码。确认按钮背后执行相同命令。确认码与本次司机、驾驶权、车辆段牌子和停车状态绑定，重新申请会使旧码失效。无参数申请仍要求当前司机持有驾驶权、车身覆盖depot并停稳，不能在任意位置遥控纳管。

提示的首次确认及确认后的释放都有时效，通常应在 30 秒内完成。移动、离车、断线、换驾驶权或改动库位可能使流程失效，需要重新停稳。

确认后仍须在30秒内显式 `/st release`；未确认时直接释放不会纳管。手动移交保留当前停放位置，不自动牵引到中心；以后自动回库仍使用中心停车。

**直接 `/st release`、离车或断线不等于同意 SAL 纳管。** 成功纳管后，列车归属更新为实际车辆段。

## 9. 在 PCC 编辑线路和查看车辆段

同一地图独立勾选工务设备、SAL设备、运营线路和实时车/MA；工务子选项可分别控制balise、END、ORIGIN、道岔。字号旁可调高亮尺寸和颜色，这些只改变显示。

用与改道岔相同的Token进入线路编辑。填写新名称、方向、GLOBAL/RESTRICTED、偏好秒数和迎车上限；选择可选偏好组或必需允许组，创建草稿。点公共station、应答器、道岔、有向图边添加访问，调整顺序、停站、折返。station条目可复制名称@访问UUID。保存→验证→发布分开操作。

草稿和发布版分离，运行任务持自己的发布快照。公共站不归某条线路，PCC编辑不改写实体牌。游戏和PCC冲突同时冻结，必须人工解消，重启不自动解决。

请求/决策面板显示QUEUED、ASSIGNED、REUSED、MERGED、REJECTED、CANCELLED，关联线路、始发点、车辆、组、迎车估计、成本和原因。ASSIGNED不代表STCS已经放行。

选择停车组高亮其全部登记列位，查看总列位、停放车辆和持SAL任务的运行车辆；停稳中的任务也算运行中，非按速度统计。停车详情保留容量、边界、单双端和计划中心。

## 10. 任务管理、故障和重启

### 10.1 查看和保持

```text
/sal status
/sal stop <列车UUID>
```

status 显示任务的列车 UUID、线路、阶段和原因。没有运行任务不代表没有列车，也不代表所有列车都可发车。

stop 使任务进入管理员保持并施加停车意图，不删除列车或清除占用。运行中的列车需要实际制动停稳。

### 10.2 恢复任务

检查列车停稳、定位可信、TIMS 完整、图及控制权正常后：

```text
/sal resume <列车UUID>
```

**resume 是恢复后先回库，不是继续载客跑完原圈。** 验证或接管不成立时会拒绝，不能靠反复执行跳过问题。

### 10.3 结束任务

```text
/sal finish <列车UUID>
```

要求列车可观测、全列停稳且无完整性保持。系统先释放旧 MA，再结束自动控制权。此命令不负责把列车送回库，也不等于 `/sal release` 的待命转手动流程；在库外结束任务后仍需按实际状态处理。

### 10.4 常见任务阶段

| 阶段 | 含义 |
| --- | --- |
| `PICKUP` | 前往首站 |
| `DWELL_PICKUP` | 首站接客站停 |
| `RUNNING` | 按线路运行 |
| `DWELL` | 中途或末站站停 |
| `RETURN` | 回库规划、等待或行驶，需结合原因判断 |
| `FINISHING` | 释放许可和自动控制权 |
| `PAUSED` | 管理员保持 |
| `RECOVERY_REQUIRED` | 重启或图依赖变化后等待确认 |
| `FAULT` | 故障保持，需要检查 |

换向、首站复用和 SR 恢复还会出现过渡阶段；阶段名本身不代表获准移动。

### 10.5 TIMS 和偏离路径

TIMS 自动恢复只针对允许自愈的暂态问题：先停稳，确认真实完整性恢复，再处理旧许可。最多尝试三次；真实缺车、异常间距、编组改变及人工 Trip 不能靠自动确认掩盖。

偏离任务路径会停止牵引并在 PCC 告警。满足停稳、完整性和定位条件后，管理员可以在 PCC 批准分段 SR 引导回库。每一段需要独立批准，到授权边界前停车；不能把一次批准当成无限回库许可。

SR 覆盖合法库位和所需余量时，允许在该授权内完成中心入位。PCC 目前没有独立远程换端按钮；不要把配置好的 station 折返和任意位置远程调头混为一谈。

### 10.6 空车与区块

STF 的列车区块票据不依赖乘客。SAL 经 STA 提交前方路径保活需求；前方区块未准备好时不提供牵引。

如果服务器启用了空服暂停，区块票据不能使被整体暂停的服务器继续运行。无人在线运行测试应同时核对服务器的空服暂停设置，例如测试服使用的 `pause-when-empty-seconds=-1`。

### 10.7 重启与数据

`plugins/SkyATO-Lite/state.json` 保存设备、归属、任务以及线路编辑状态。不要在运行中手改，也不要用删除它来消除占用或解冻冲突。

重启后旧任务进入 `RECOVERY_REQUIRED`；停车目标即使已持久化，也不会自动发车。检查后按 resume 流程处理。占用账本缺少出清证据时仍应保留。

## 11. 完整指令速查

参数中的尖括号表示需要替换，方括号表示可选；不要原样输入括号。

### 11.1 玩家与司机

| 指令 | 用途 |
| --- | --- |
| `/sal help` | 查看当前权限可用的帮助 |
| `/sal release` | 坐在回库自动待命车中，释放待命后转手动 |
| `/sal handover` | 车身覆盖depot并停稳时，立即申请随机六位码 |
| `/sal handover <六位确认码>` | 确认本次纳管，然后显式 `/st release` |

### 11.2 管理员：线路

| 指令 | 用途 |
| --- | --- |
| `/sal route create <线路> [偏好停车组[,停车组]]` | 新建GLOBAL草稿；玩家朝向作为初始方向 |
| `/sal route direction <线路> <north\|south\|east\|west>` | 修改首站运行方向 |
| `/sal route depot <线路> <停车组[,停车组]\|none>` | GLOBAL设置可选偏好；RESTRICTED设置必需允许组 |
| `/sal route bind <线路>` | 绑定附近候选设备 |
| `/sal route bind <线路> <设备UUID或station完整ID> [reverse]` | 精确绑定一次访问；reverse 只用于 station |
| `/sal route bind <线路> reverse` | 选择附近设备，并将此次 station 访问设为折返 |
| `/sal route choose <编号>` | 选择最近一次 bind 提示中的候选 |
| `/sal route list <线路>` | 查看草稿访问点、版本和编辑参与者 |
| `/sal route remove <线路> <序号>` | 删除草稿中的一次访问，序号从 1 开始 |
| `/sal route preview <线路> [off]` | 开启或关闭个人粒子预览 |
| `/sal route validate <线路>` | 验证草稿 |
| `/sal route publish <线路>` | 验证并发布新版本，成功后关闭游戏编辑会话 |
| `/sal route close <线路>` | 关闭自己的游戏编辑会话 |
| `/sal route resolve <线路> DISCARD` | 人工丢弃冲突提案，解除冻结 |
| `/sal route resolve <线路> <参与者actor>` | 人工选择要采用的提案 |
| `/sal route retire <线路>` | 停用线路，阻止新的叫车 |
| `/sal route delete <线路>` | 删除线路；有相关活动任务时拒绝 |
| `/sal route supply <线路> global\|restricted [偏好秒数] [迎车上限秒数]` | 设置供车策略，需重新验证发布 |
| `/sal station list` | 公共停车点名称和ID |

游戏内 direction、depot、bind、remove 等成功操作会保存草稿，没有另外的 `/sal route save` 命令。PCC 则需要显式点击保存草稿。

### 11.3 管理员：列车和任务

| 指令 | 用途 |
| --- | --- |
| `/sal train home` | 坐在列车内查询车辆段归属 |
| `/sal train home <车辆段>` | 坐在列车内绑定归属；有任务时拒绝 |
| `/sal awake <线路> <停车点[@访问UUID]>` | 指定本次始发的共享叫车 |
| `/sal status` | 列出任务、队列及最近派车决策 |
| `/sal override <列车名或UUID>` | 管理员脱困：停车、撤权确认、退出SAL，持久保留手动状态 |
| `/sal stop <列车UUID>` | 管理员保持 |
| `/sal resume <列车UUID>` | 核查后恢复为先回库任务 |
| `/sal finish <列车UUID>` | 停稳后释放许可并结束任务 |

## 12. 配置文件

位置：`plugins/SkyATO-Lite/config.yml`。

```yaml
# 默认任务巡航速度，单位为方块/tick；仍受车型和ATP限制。
cruise-blocks-per-tick: 0.4

depot:
  # 相邻库位合计的净间隔，每侧承担一半。
  net-gap-blocks: 2.0
  # 道岔或尽头边界的停车余量。
  boundary-margin-blocks: 2.0
  # 围绕计划停车中心预留的停车误差，不是允许越界挪位的范围。
  stopping-tolerance-blocks: 0.5

dispatch:
  batch-window-ms: 500
  request-timeout-ms: 120000
  compute-budget-ms: 500
  last-vehicle-penalty-seconds: 0
```

| 参数 | 允许范围 |
| --- | --- |
| `dispatch.batch-window-ms` | 100–5000毫秒 |
| `dispatch.request-timeout-ms` | 5000–600000毫秒 |
| `dispatch.compute-budget-ms` | 50–2000毫秒 |
| `dispatch.last-vehicle-penalty-seconds` | 0–3600秒，0关闭近似库存罚分 |
| `cruise-blocks-per-tick` | 有限数，0–100；实际速度仍受其他限制 |
| `depot.net-gap-blocks` | 有限数，不小于 0 |
| `depot.boundary-margin-blocks` | 有限数，至少 1 格 |
| `depot.stopping-tolerance-blocks` | 有限数，0.06–0.75 格 |

旧配置缺少这些键时使用默认值。建议停服备份后修改并重启，不提供通过 reload 热切换运营状态的流程。

## 13. 常见问题

| 现象 | 优先检查 |
| --- | --- |
| 提示“车辆段不存在” | 是否先成功登记了至少一块对应 depot 牌 |
| 请求未分配 | 当前发布策略、迎车估计上限、路径、硬过滤及排队超时原因 |
| 没有可用列车 | home、手动待命状态、驾驶权、已有任务、TIMS、完整车身观测和被其他列车阻挡的路径 |
| 按钮没有反应 | 牌头和逐行字段、供电上升沿、首次初始化、防连点、线路是否发布 |
| 有空位却不回库 | 库位容量、预约、完整车身空间、入口是否被车挡住、STCS 实际 MA |
| 库位边界未确认 | 是否止于 ORIGIN／未知图边界、缺少反向连接或存在拓扑故障；不要直接删除账本 |
| 车头到了牌子却不纳管 | 无手动司机的自动停车捕获仍看中心；手动司机纳管只需车身覆盖牌子，可执行 `/sal handover` 申请六位码 |
| 手动车停稳后没有确认按钮 | 驾驶权、车身是否覆盖depot、TIMS和停稳状态；等3秒自动提示或执行 `/sal handover` 立即申请；直接 `/st release` 不触发纳管 |
| 绿色预览但车不走 | 绿色只说明拓扑验证，继续检查 MA、区块、道岔确认和列车保护状态 |
| 最短走法不是预期路线 | 添加预期分支上的应答器／道岔，或用PCC选择有向轨道边；多条可行路径本身不再报错 |
| 编辑被冻结，重启也无效 | 检查两侧提案并人工 resolve；不要让两侧继续尝试保存 |
| resume 后没有继续载客 | 这是预期行为：恢复先回库 |

## 管理员脱困快捷流程

/sal override test2 → /sal status 确认完成 → 坐驾驶端 /st drive。普通司机不能用override，仍用原纳管／释放流程。移动、旧观测、不同owner或STCS未确认时等待，不清账本。TIMS、TR/PT可能还需正常人工处理。重启丢失旧会话时先由STCS确认无执行许可。详见[接管与坡道契约](../Common/doc/SAL-OVERRIDE-AND-SLOPES.md)。

## 定位容差与原始故障

新增localisation.position-tolerance-blocks（默认1.5，0.25–2）、endpoint-tolerance-blocks（默认0.75，0–1）、confirmation-ms（默认2000，100–10000整数）。复核期间制动，不扩MA。确认恢复仍受独立ATP/TIMS保护。/sal status与PCC保留最初故障，不再被“等待SR”覆盖。[规则与测试](../Common/doc/SAL-LOCALISATION-TOLERANCE.md)。

## 回库复核与历史记录

新增depot.recheck-ms，默认2000ms、范围100–10000整数。复核中制动并续租已有进路，车身未知不当成拓扑变更不断重选；持续未知会FAULT。空间／库位真实变化停稳后重选。/sal status将最近派车历史单独标明，不当作活动任务。[详细规则](../Common/doc/SAL-RETURN-RECHECK.md)。
