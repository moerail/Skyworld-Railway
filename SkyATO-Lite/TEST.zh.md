**[新增 · SAL0.7.6 · 2026-11-26]** 叫车队列和超时结果新增逐车原因：未参选的状态／归属／手动保留／任务／观测／TIMS／车身条件；正反向路径与接客估计上限；阻断的其他列车名称、观测年龄、缺失或无法匹配图的车身位置；实际车身挡住的轨道边，以及图版本／计算时效变化。保持原安全条件，不自动解除TIMS或忽略其他列车。其它列车仅有TIMS保持本身并不造成全局阻断。诊断数量有上限，不显示为已穷尽全网。

日期：2026-11-26。

**本轮诊断功能需要同时更新 STA2.9.2、SAL0.7.6、PCC2.6.4，不能只换PCC。** 若已安装上一轮配套，STF5.1.2与STCS4.3.5不变；保留配置和数据，更新后Ctrl+F5。触屏拖动采用Pointer Events，当前自动化已验证鼠标与键盘，手机／平板仍需真机验收。

适用起点：主城停车组已有两列待命车，分别停在 **L5-1、L4-1**；还没有在 PCC 配置有效运营线路，也没有新的公共 station、awake 等运营牌。

本手册不要求重建列车、改动既有 depot、清账本或删除旧状态。文中示例停车组为 `maintown`，请以实际名称替换；**“主城”是描述，不保证实际组名就是 `maintown` 或 `主城`。** 测试期间先保持两车静止，逐步开放发车。

## 0. 更新前：确认五个插件整套配齐

| 插件 | 本轮版本 |
| --- | --- |
| SkyworldTrainAPI / STA | **2.9.2** |
| SkyTrainFolia / STF | **5.1.2** |
| STCS | **4.3.6** |
| SkyATO-Lite / SAL | **0.8.0** |
| SkyPCC | **2.6.4** |

1. 正常停生产服，备份五插件配置和数据、列车、RailGraph、世界、SAL state、所有占用账本。
2. 使用同一分发包 `plugins/` 中的五个 JAR，按 `SHA256.json` 校验；移走这些插件的旧 JAR，避免重复安装。STF/STCS 版本号虽未变，也建议使用本轮配套构建。
3. 保留原有配置和数据。缺失的新 SAL 配置键有默认值，首次不必调整。
4. 完整启动生产服，检查上述实际加载版本。出现 `NoClassDefFoundError`、`NoSuchMethodError` 或类缺失，先停止测试核对配套，不能靠清数据处理。
5. 刷新 PCC：Ctrl+F5。控制 Token 沿用既有 Token，不需要重新生成。

**本轮没有替你在生产服安装或启动。** 本地测试服已关闭，以下步骤由生产管理员执行。

## 1. 保留并检查 L5-1、L4-1 两列待命车

在 PCC 选择主城实际停车组，确认两列车和原来的两个库位仍在。

逐列坐入，仅查询：

```text
/sal train home
```

记下各车的列车 UUID、实际停车组名。此时不需要 `/sal release` 或 `/st drive`，避免主动解除已有待命。

预期：两车属于正确组、完整性正常、无当前驾驶员、没有运行任务，并已成为自动待命车。`/sal status` 只列任务，不是完整待命车名册；“没有任务”不等于“没有待命车”。

若某车尚未纳管，才执行修复流程：由其司机保持驾驶权，让车身任意部分覆盖对应 depot，停稳 3 秒获得六位码，或停稳后 `/sal handover` 立即申请；再 `/sal handover 本次六位码`、`/st release`。不要为测试随意重新绑定两车归属。

## 2. 先登记公共停车点，不用先创建线路

选择一条已在 STCS RailGraph 中连通、能够验证循环、且不把停车点放在道岔安全范围内的线路。

第一站，四行分别写：

```text
[SAL]
station
15
MainStart
```

另一站写：

```text
[SAL]
station
10
Scenic
```

第四行是**停车点名称**，不是线路名；名称在服务器内唯一。两块牌都放在对应轨道柱下，不能悬空或指向尚未建图的轨道。

检查：

```text
/sal station list
```

预期：能看到 `MainStart`、`Scenic` 及各自 `station:...` 设备标识，PCC 中出现对应公共停车点。放牌不会自动生成或追加运营线路。

若看到旧名称变成 `旧名_S序号`，那是旧数据迁移名称；保留引用，不必删牌重建。实际旧牌文字可后续按新规则重写。

## 3. PCC 创建第一条有效运营线路

1. 点击“进入运营线路编辑模式”，输入既有控制 Token。
2. 新线路名称填 `MainTour`，避免覆盖不确定的旧线路。
3. 车辆来源选 **全局共享车池**。
4. 偏好停车组选主城的实际组名。
5. 偏好容忍代价先填 **30 秒**。预计接客上限可先填 **300 秒**，避免第一次因估计距离过长而排除两车；熟悉后再缩小。
6. 选择 MainStart 的初始运行方向。
7. 点击创建草稿。
8. 按实际行驶顺序选点：`MainStart → 必要中间设备 → Scenic → 必要中间设备 → MainStart`。相邻两次访问间必须能确定唯一合法路径，有分支时补应答器、道岔或有向轨道边。
9. 核对站停秒数。只在确实需要停稳换向的 station 访问上勾选折返。
10. 依次点击 **保存草稿 → 验证草稿 → 发布新版本**。
11. 退出编辑模式。

预期：出现发布版 v1，线路在同一地图上按已发布线型显示。保存或验证成功，都不等于已经发布。

绿色、闭环和已发布不等于取得 MA；尚未按按钮时两列车应继续待命。

## 4. 第一轮：从 MainStart 叫车

先使用管理员命令，减少红石接线变量：

```text
/sal awake MainTour MainStart
/sal status
```

预期：请求先进入队列，短暂汇集后由后台计算。PCC 的“派车队列与结果”显示 `MainTour @ MainStart`、选中车辆的停车组、预计接客时间、成本和原因；随后只应有一列车承担本次接客。

观察：

- L5-1、L4-1 中可行且成本较低的车被选中；不是固定按库位名称排序。
- 如果朝向相反，可以先停稳释放旧许可并换向。
- 道岔按进路处理，不要求提前人工扳好。
- 获有效 MA 后才运行，可能因实际进路条件等待。
- 到 MainStart 停稳，必要时调整发车方向，再开始接客站停。
- 按 `MainStart → Scenic → MainStart` 完成一圈，最后回到适合的库位中心停车。

预计接客是粗估，暂不完整模拟所有限速、加减速与拥堵；不能把秒数当作准点承诺。

## 5. 设置两处 awake 按钮

MainStart 按钮的牌子：

```text
[SAL]
awake
MainTour
MainStart
```

Scenic 按钮的牌子：

```text
[SAL]
awake
MainTour
Scenic
```

按钮给牌子或支撑方块供电，使用真实供电上升沿。**第三行是运营线路，第四行是始发停车点，已经不是“车辆段／线路”。**

初次电平初始化或持续通电不会连续叫车；首次无反应时释放再按。短时间连点有防抖，同入口已有待派／接客请求会合并。

旧格式 awake 在迁移后保持停用，必须由管理员按新格式重写，不能只把旧按钮接回去。

## 6. 从 Scenic 始发，验证任务旋转

等两车回到待命，执行：

```text
/sal awake MainTour Scenic
```

预期：本次任务从 Scenic 接客，运行 `Scenic → MainStart → Scenic` 后回库。PCC 中 MainTour 的发布版仍为 v1，不会因为从另一站始发而重写原线路。

若同一站在线路中有多次不同访问，直接使用站名会明确拒绝歧义。到 PCC 编辑列表复制想要的 `名称@访问UUID`，再填写 awake 第四行或作为命令参数：

```text
/sal awake MainTour Scenic@这里替换为真实访问UUID
```

上面的文字不是可直接执行的 UUID。闭环最后重复首站只是闭合访问，不是另一个可选始发入口；应复制真实访问项的引用。

## 7. 验证两列车不会被重复分配

让两车都待命，在一个调度窗口内从两处不同入口叫车：

```text
/sal awake MainTour MainStart
/sal awake MainTour Scenic
```

预期：同一列车最多分给一个任务；若两车都满足条件，可以分别接客。STCS 仍可能让其中一列等同一道岔或区段，匹配成功不意味着同时放行。

如果有一个请求暂时没有车，应该继续排队并显示原因，而不是抢走已执行任务的车。默认 120 秒后未匹配会有超时结果。

再对同一入口重复按按钮：预期合并待派或接客请求，不不断拉车出库。

## 8. 验证始发站复用

在列车停靠本次始发点、仍未离站时，对相同线路和入口再叫一次。

预期：复用同发布版、同始发访问的车，刷新站停，不额外派另一列。列车已离站后再次叫车则可以形成新的接客请求。

## 9. 偏好阈值与跨组：当前两车能测什么

两车都在主城同组时，可以测试成本选车、不同入口和批量分配，**不能仅凭这两辆车验收跨组偏好回退**。

跨组验收需要另一个真实停车组有一辆已纳管、可达的待命车。不要仅修改 home 标签假装另一个车辆段，也不要为了这个测试拆改 L5-1／L4-1。

具备条件后，在 PCC 将主城设为偏好、来源选全局；分别观察偏好车稍慢但仍获选、偏好车明显更慢而共享车获选。30 秒是有限罚分，多请求时整体最优可能影响单个请求的选择。

将来源改为“仅选中停车组”，保存、验证、发布后，该发布版只从选中组取车。切回全局也要明确发布。已有任务固定旧发布版，不受草稿编辑影响。

## 10. 可选：速度和乘客消息

在运行轨道柱下放：

```text
[SAL]
property
V_target
36km/h
```

以及：

```text
[SAL]
message
欢迎乘坐主城环线
5
```

预期：巡航目标仍受列车和 ATP 限制；乘客看到中央文字，后续 message 覆盖前一个。建议第一圈先不加入这些变量，基础出入库正常后再加。

## 11. 失败时收集什么、怎样停住

记录发生时间、实际五插件版本、列车 UUID、线路名及发布版、始发引用、`/sal status` 和 PCC 原因。需要时附当前图版本、道岔和 MA 状态，避免只截图“车没动”。

管理员保持任务：

```text
/sal stop 这里替换为真实列车UUID
```

核对停稳、定位与完整性后，`/sal resume UUID` 会先回库，不继续原载客循环。`/sal finish UUID` 只在条件满足时释放许可和任务，不负责自动送回车辆段。

不要以清占用账本、强开道岔、删除列车或删除 SAL state 的方式处理首次测试失败。若需回滚，停服并使用同一备份中的配套二进制和数据；新 schema2 状态不要交给旧 SAL 读取。

## 附加：线路编辑交互验收

- 用右侧≡手柄将一项拖到另一项前后，松手后确认顺序、访问UUID、停站和折返属性。草稿尚未保存，发布版不变。
- 触屏长距离拖动靠近侧栏边缘可自动滚动；取消手势或按Esc，应恢复原顺序且不提交。也可聚焦手柄按上下方向键。
- 对确实不可达或方向不符的相邻访问验证：应显示两端序号、名称、ID和原因，两项标红；点诊断可跳转。修正后再次验证，诊断应清除或推进到下一个真实失败点。多条可行路径现在自动选最短，不作为报错用例。不要为触发报错破坏生产轨道或已发布任务。

## 附加：叫车拒绝诊断

已安装STA2.9.2、PCC2.6.4的用户仅需换SAL0.7.6，保留配置和数据，完整启动后重新叫车一次。观察PCC队列原因或 /sal status；旧历史记录不会补出之前未记录的细节。

PARKED加TIMS CONFIRMED仍不能证明车身每节都已在图上定位。若显示其他列车名称与bodyKnown=false／过期／无法匹配轨道图，先核对该列车真实位置和RailGraph；若显示接客时间超过上限，核对该发布版策略；若正反向均无合法路径，检查有向连接及是否依赖途中折返。不要为了诊断清占用账本或把所有TIMS保持一并解掉。实际生产根因以新报告为准，本次离线测试不能替代生产日志。

## 附加：坡道与管理员override验收

本轮同步替换STA2.9.2、STF5.1.2、SAL0.7.6，不能只换SAL。现有卡住的test2可先 /sal override test2，再 /sal status 等完成后 /st drive。PCC车身占用仍应存在，TIMS/Trip保持不应被清除。验证手动保留不会再次自动纳管。

重新明确纳管后低速测试原坡道上坡、下坡、坡顶，记录时间及具体SAL定位原因。另测行驶中override只先制动，STCS未确认撤权时不释放控制、重启丢失旧会话时不清不确定占用。本轮没有生产服实车验收；[详细规则](../Common/doc/SAL-OVERRIDE-AND-SLOPES.md)。

## SAL 0.8.0 / STF 5.1.4 增量生产测试

停服备份后替换SAL与STF，配套STA2.9.2、STCS4.3.6、PCC2.6.4；保留所有线路、列车、设备和账本。现有活动任务重启后需先按RECOVERY_REQUIRED处置，不能直接认为会续跑。

1. **纳管**：取得手动驾驶权，任意一节或车身中间覆盖depot牌停稳3秒。应收到六位码；可用 /sal handover 查看明确的不满足原因或立即申请。等待旧码过期，应收到新码且旧码不能确认。确认后仍须 /st release；直接释放不纳管。
2. **途中折返接客**：选择必须先驶出咽喉、整列出清、再换向才能到站的库位。按awake叫车，观察/sal status的机动段与换向次数。列车应先停稳，再完成旧MA释放及换向，新方向确认后继续；不能车尾仍压道岔就换向。路径若超过接客时间上限仍会被排除。
3. **回库与双车**：完成一圈后回库，测试需要途中折返的库位，并让另一车正常使用咽喉。原双车排队规则继续有效，自动排道岔不得撤销另一车MA，最终仍中心停车。
4. **拒绝场景**：短折返股道、缺反向边、被占用的折返位置、TIMS保持、TR/PT和真实断轨，均不能强制换向。搜索预算耗尽应等待/报原因，不执行部分路线。重启后不得自动重放旧换向动作。
5. **hotbar**：手动车 /st drive，选第5格后 /st hotbar，选方向和牵引档，驶过区块边界。等待区块时手柄应保留，实际牵引被禁止并保护制动；就绪且MA有效后按当前手柄运行。期间改N或制动必须保留新选择。若仍归零，记录当时ATP/TIMS/CHUNKS_LOADING原因及驾驶权状态。

完整边界与说明见[本版说明](../Common/doc/SAL-MANEUVERS-AND-HANDOVER.md)。离线测试不等于生产验收。
