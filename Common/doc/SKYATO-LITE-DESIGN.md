# SkyATO-Lite：预设线路叫车与回库

状态：0.2.0 隔离测试候选的需求与设计记录。实际语法和使用步骤见 `../../SkyATO-Lite/README.md`。
图版本与卸载处理以 [RailGraph 增量契约](RAILGRAPH-INCREMENTAL.md) 为准：无关变更保持发布，受影响线路重验。
STA v8 编号、官方依据及兼容边界见 [ATO 协议契约](STA-V8-ATO-PROTOCOL.md)。
离线回归通过不等于现有线路实服验收。
独立插件 SkyATO-Lite；不替代原版 SkyATO 的完整调度规划。

## 1. 已确认的运行规则

- 管理员按顺序绑定现有应答器、道岔节点及停车点，构建固定运营路线。
- 叫车后，从指定车辆段中选择可用列车，经出库路径前往线路的第一个 station 接客。
- 列车执行一次线路任务，到最后一个 station 完成停站后回库；不因乘客仍在车上而追加一圈。
- 乘客可以跟车回库，不强制下车；再次乘坐一圈需要回到站台触发 awake。
- 乘客中途下车不取消或缩短本次线路任务。本条取代早期“空车立即回库”的讨论。
- 车辆段是逻辑集合，可以包含分散的多个停车位；不要求停车位集中在一个场地。
- 列车固定归属车辆段，不固定归属停车位；回库时查找并预约合适的空闲停车位。
- 不使用出生新列车的方式响应叫车，不复用假玩家身份申请 MA。

## 2. 牌子

两个等价牌头：`[SkyATOL]`、`[SAL]`；解析忽略大小写。
牌子的创建、修改、移除属于管理员操作；玩家只触发已授权叫车入口。
SAL 牌子必须由独立处理器识别，不改变 STF 旧 station/property 等牌子的语义。

| 第二行 | 第三行 | 第四行 | 含义 |
| --- | --- | --- | --- |
| depot | 车辆段唯一名称，例如 maintown | 停车位名称，例如 L1 | 登记独立停车位；唯一键为车辆段名称 + 停车位名称 |
| awake | 车辆段名称，例如 maintown | 运营线路名称，例如 Line1 | 红石上升沿触发一次叫车请求 |
| station | 停站秒数 | SAL 运营线路名称 | 身份由牌子位置确定；按线路访问角色区分接客与终到 |
| v_target | 巡航速度，单位同 STF | 留空 | 改变后续任务巡航目标，不授予 MA，不解除制动，不提高线路或车型上限 |
| property | V_target | 巡航速度，单位同 STF | 与 v_target 简写等价 |
| message | 字面文本 | 显示秒数 | 本车乘客中央 Title，新消息覆盖旧消息，不执行任意指令 |

用户确认的示例：

```text
[SAL]
depot
maintown
L1
```

```text
[SAL]
awake
maintown
Line1
```

L2、L3 等停车位用各自 depot 牌子登记。叫车统一通过 awake 定义车辆段与线路，
不把第四行自动猜测为停车位名。首版不引入 `Line1@L2` 等未经确认的语法。
同一车辆段可服务多条线路；只能分配在图上能到达接客站且能返回该车辆段的列车。

depot/station/v_target/message 关联其上方轨道，沿用可复用的轨道牌柱关联规则，
不能按球形最近距离误绑平行轨道。awake 是远程叫车入口，不要求自身在轨道牌柱下。
按钮给 awake 牌子或其支撑方块供电；持续供电不重复派车，启动时已有电平不自动触发。

## 3. 列车归属与停车位分配

列车绑定指令：

```text
/sal train home <车辆段名称>
/sal train home
```

管理员坐在列车内执行第一条，把当前完整编组的 `homeDepotId` 绑定到该车辆段。
第二条只查询当前车的归属、实时所在停车位和预约停车位。名称最终以实现时帮助为准。

- 只绑定元数据，不因执行绑定而立即启动列车或改变当前驾驶权；不存在的车辆段拒绝绑定。
- 列车靠稳定编组 UUID 识别，不以管理员当前乘坐的单节矿车 UUID 代替整列车。
- 绑定不固定 L1/L2/L3；实际回库前，按方向可达性、整列长度、占用、预约和观测有效性筛选停车位。
- 选定后原子预约：同一停车位不能分配给两列车；实际停稳且全列进入后才转为停放状态。
- 没有合适停车位时，停在任务中预设的安全等待点并显示原因，不随机停在道岔上。
- 任务正在执行时拒绝改归属，须先停稳并结束或撤销任务，避免回库目标被中途替换。
- `homeDepotId`、实际停放位置与停车位预约是不同状态。只保存了归属不能证明车辆空闲或已经入库。
- 载人回库不自动开启下一次服务；车上乘客不等同人工司机，不可据此获得控制权。

## 4. 线路编辑与粒子预览

线路编辑命令族（实际帮助以 `/sal help` 为准）：

```text
/sal route create <线路名>
/sal route bind <线路名>
/sal route choose <候选编号>
/sal route list <线路名>
/sal route remove <线路名> <序号>
/sal route preview <线路名> [off]
/sal route validate <线路名>
/sal route publish <线路名>
```

管理员站在设备附近执行 bind，在有限半径内从图设备快照找候选：

- 只有一个候选：显示设备类型、名称、位置及 UUID 后绑定。
- 多个候选：列出编号与信息，等待管理员选择；不能直接取最近者。
- 候选选择绑定管理员、线路草稿版本和图版本，短时有效；过期或设备已变更必须重新查询。
- 稳定设备 UUID 作为引用；道岔另存入口/出口方向。存在分支歧义时要求补充路径或端口。
- 邻近设备搜索不是对未加载区块进行同步实体或方块扫描。

按有序节点补齐沿线 RailGraph 几何，在轨道上方显示采样粒子，默认仅编辑管理员可见。
未闭环、断路、路径歧义或图引用失效为红色；已验证有向闭环为绿色。
闭环必须包含实际行驶区间，不能用单节点或零长度路径判定成功。
折返是显式停稳换向步骤，闭环需检查回到起点时方向也符合下一次运行要求。
草稿关闭预览或超时后停止粒子；按可见距离和点数限制负载。

绿色只表示当前版本的运营路径闭合，不代表实时空闲或已获 MA。
另行校验各可用车辆所在位置到首站的出库路径、末站到归属车辆段停车位的回库路径。
图版本或被绑定设备变化时，旧验证失效，重新检查后才接受新任务。
编辑草稿不改变已经运行的任务；运行任务固定线路版本。

## 5. 调度与行车边界

单次任务：

`待命 -> 预约列车 -> 申请出库进路/MA -> 首站接客 -> 按序运行/停站 -> 末站停站 -> 预约回库位 -> 回库 -> 停稳结束`

接客等待结束后执行单次路线，无人上车也完成一次任务；不沿用旧讨论中的“超时直接回库”。

- awake 同一入口重复触发应合并已存在的待接客请求，避免连点耗尽车队；具体冷却可配置。
- 选择列车必须原子占有任务，且停稳、成员观测完整新鲜、无人工司机、无其他任务。
- 没有可用列车时向入口反馈，不无限积累无人等待的叫车任务。
- SkyATO-Lite 只提交预期路径和驾驶意图。STCS 核实占用、道岔转换确认及锁闭后授予可执行 MA；STF 执行牵引制动。
- 道岔请求已发送不等于开向已确认；有路径不等于有 MA；图上无列车图标不等于轨道空闲。
- 折返须全列停稳、完整性及空间满足、切换驾驶端，并重新申请返向进路与 MA。
- 缺失实体、未知占用、定位/许可失效、图设备删除或重启进入恢复保持，不自动清空占用或强制发车。
- message 按本次任务、路径点访问次数去重；乘客使用自身实体调度器接收信息，跨区不直接读取车辆实体。

## 6. 当前源码可复用项与缺口

已读源码证据：

- `STA/.../api/v5/RailNetworkService.java`：只读图版本、图 JSON、位置/下一设备查询、可选边位置与站点预告。
- `STCS/.../RailGraph.java`：节点、带入口/出口的边及轨道几何，可作为绑定与预览基础。
- `STA/.../api/v7/StationAreaService.java`：只读站场配置快照；不授予进路或 MA。
- `SkyTrainFolia/.../RailSignAccess.java`：Folia 区域内轨道牌柱关联。
- `SkyTrainFolia/.../AutomaticSigns.java`：现有 station 停站与目标速度；不是自动任务的 MA 接入接口。
- `Common/doc/BASIC-AUTOMATIC-SIGNS.md`：现有伪 ATO 明确不提供占用防护与 MA enforcement。

当前候选已加入：独立插件工程、SAL 注册/监听、路线模型和编辑、粒子、停车位分配与任务持久化，
以及 STA v8 自动任务身份、过期控制意图、递增请求序号和释放 fencing、指定路径的 STCS MA 接入。
STF 执行物理控制、中央 Title 和异步区块票据。单车闭环已完成隔离实测；下一步需要实际站场、多车与故障注入验收。
不得绕过接口直接调用包私有 RailGraph，也不能把公开 graphJson 只读接口视为调度服务。

首轮验收至少覆盖：多设备选择、断环/闭环/折返方向、重复按键、双车抢同位、双入口抢同车、
不可达停车位、载人回库不自动再跑、道岔拒绝或未确认、MA 撤销、成员丢失、重启后保持。

## 7. STF 配套升级：默认申请 FS

用户要求手动与自动列车均默认使用 FS。将驾驶方式 MANUAL/AUTOMATIC 与保护模式分开：

- 正常启动默认启用可执行保护，并以 FS 为默认申请目标；不再把新启用的自动列车放在无 MA 的伪 ATO 旁路上。
- 启动/接管时仍从 SB 或恢复保持开始，完整性、位置、驾驶控制权及可执行 MA 验证成功后进入 FS。
- 手动列车由真人取得驾驶权后自动发起 FS 申请；自动列车由有效任务取得自动控制权后申请。
- 无司机也无有效任务的列车保持停车，不因插件启动而申请许可或自行发车。
- 未连接 STCS/许可服务不可用时保持待命，不回退为无保护牵引。不得仅把模式字段改成 FS。
- 默认 FS 不等于永远 FS；故障、撤销、人工切换 SH/SR 或 TR/PT 恢复仍遵循各自条件。
- 旧列车配置、旧伪 ATO 以及 SHADOW/ISOLATED 的迁移需要明确升级说明；不得在行驶中静默改变保护通道。

## 8. STF 右侧计分板

复用现有 CabUiManager，不由 SAL 创建第二套竞争 sidebar。
通过 STA 的不可变任务状态快照向 STF 提供：控制者（真人/虚拟司机）、线路、下一站、
任务阶段（出库/接客/运行/回库/待命/恢复）、目标车辆段/停车位、恢复状态及等待原因。
STF 负责布局与本地化，保留当前速度、巡航目标、实际保护模式、MA 状态/余量和 TIMS 摘要。

- 默认 FS 申请中与实际 FS 清楚区分，自动驾驶不能再只显示一个“自动”覆盖实际保护状态。
- 制动保持原因、MA 不可用与 TIMS 故障优先于非关键任务信息；按 sidebar 行数预算合并显示。
- SAL 不存在或没有任务时不影响普通手动车界面；状态快照过期显示不可用，不继续展示旧的正常状态。
- 自动列车乘客显示精简行程信息；完整驾驶/故障信息留给司机或授权管理视图。

## 9. 自动列车 TIMS 自愈

用户要求虚拟司机识别 TIMS 报错并重启自愈。首版“重启”限定为停稳后的自动控制会话重建与
原列车成员观测恢复，不 reload 插件/服务器，不销毁重生车辆，不传送载客编组，不重写编组名单。

`识别故障 -> 停止牵引/保持制动 -> 停稳并处理旧许可 -> 重建控制会话/重新采样 -> 核实完整性 -> 有条件确认 -> 申请新 MA -> 恢复任务`

- TIMS 是 STF 的原始证据来源，SAL 不得自己修改或伪造 COMPLETE，也不直接清除 latched 标志。
- 保留原始成员 UUID、故障原因、任务进度、车身占用和停车位归属；旧控制会话必须被 fencing，不能和新司机同时控车。
- 定位与全列停稳证据不足时等待，不提前释放前方预约或车身占用；旧许可撤销完成前不接受新会话牵引。
- 暂态采样/区块或成员调度延迟只允许在恢复真实、持续、新鲜且非 DEBOUNCING 的完整观测后进入确认流程。
- 现有 TrainIntegrityMonitor.acknowledge 要求全列停稳、状态 COMPLETE、证据新鲜且无永久故障；新接口必须复用这些条件。
- 确认 TIMS 不等于确认 TR/PT、解除紧急制动或恢复 FS；保护状态机的后续恢复条件必须逐项满足。
- 真实缺车、成员重复、编组变化、间距异常或路径歧义不能靠重启强行掩盖。
  自动恢复首版不自动确认这些高风险原因；原成员重新找到后仍可显示已恢复观测，等待管理员核实。
- 恢复需有限次数、退避和总超时；建议初始最多 3 次，数值待实现时配置。超限保持制动并给出具体原因，禁止无限重启。
- 手动列车也采用默认 FS，但本节自动恢复行为只对有效自动任务启用；真人驾驶保留现有明确确认流程。

补充验收：两种驾驶方式默认申请 FS、无 STCS 不牵引、旧许可延迟回包、暂态 TIMS 自愈、
真实缺车不被确认、恢复重试耗尽、恢复时载客、控制会话重建后仅有一个驾驶者、sidebar 与实际保护状态一致。
