# SAL最短有向路径与轨道预览

**[新增／修正 · 2026-11-26 · SAL0.7.5 / PCC2.6.4]** 轨道坐标和方向统一取自同一份STF遥测，避免转弯时混用不同帧。定位暂态立即制动、默认复核2秒；节点容差0.75格、投影误差仍默认1.5格，均可有限配置。两份独立观测确认不同分支则提前恢复；不新建或扩大MA。原始故障持久保留并在PCC事件正文与/sal status直接显示。 [详细契约](SAL-LOCALISATION-TOLERANCE.md)

2026-11-26，SAL0.7.2 / PCC2.6.4 / STA2.9.1。

**[修改]** ~~访问点之间必须只有一条路径，多条路径一律拒绝~~。每段现在按RailGraph中累计轨道长度选择最短合法有向路径。长绕行、绕环后再返回的替代路径不使短路径失效。同长方案按稳定设备／边标识及路径序列确定选择，不依赖图数组枚举顺序。

设备绑定仍是有序约束。想走另一条股道或较长路线，显式添加该股道上的应答器、道岔或有向轨道边，不要指望网页自动知道运营意图。最短是图距离，不是时间、拥堵、优先级或乘客需求；也不实现任意位置折返。

规划仍遵守当前方向、STCS道岔允许转换及图中阻断；不依赖游戏里当前扳向。存在已证实断路、方向不符、定位不确定或搜索超限仍拒绝并给出区间诊断。不能为了连接成功而自动反转或忽略图故障。最短可达也不等于MA；执行仍由STCS裁定、STA传递、STF操作实体。

同一点再次访问必须经过正长度路径，不能用零长度投影冒充一圈。首尾station、整圈闭合和到达方向检查继续保留。每段最短选择不等于对全路线所有到达方向组合求全局最优；需要指定分支时补中间访问。最短算法仍有4096步与256边预算，不保证无限大网络穷尽。

验证、始发点旋转、任务站间运行、预览统一使用同一plan选择逻辑；出入库继续使用同一最短路引擎及车身障碍约束。运行任务的发布快照机制不变。

PCC完整可行线路按实际轨道采样高亮。未完成／未闭合草稿中，可确认的前缀同样沿轨道绘制，并保留草稿线型。首次失败后不猜测后续到达方向，未确认段才画估计连线；不能将估计线误认作铁轨。颜色、线型、图层和高亮大小设置继续可用。

## 验收

1. 先保存原有草稿。在有短直达与长绕行的两个点之间验证，应选短路而不报多路径。
2. 检查PCC预览是否经过真实弯道，而非两端直线。仅首站＋中间设备的未完成草稿，其可确认段也应沿轨。
3. 添加较长分支上的有向边，确认预览尊重它；删除该约束后回到最短走法。
4. 只有当前位置通过一圈才能再次到达的同站目标，应显示完整正长度环路，不接受原地零长度。
5. 真正断路或方向错误仍显示问题区间；不要在生产轨道上人为断轨来测试。
6. 保存→验证→发布明确完成后再叫车。绿色／沿轨预览不代替区段许可。
