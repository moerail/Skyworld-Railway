## 自动待命交还手动

坐进已经回库、停稳并处于 PARKED 的列车，执行：

```text
/sal release
```

STF在实体所属线程保持制动、释放停车会话并切换为手动。随后坐在首节或末节车厢执行：

```text
/st drive
```

无需再设置 mode manual。正在运行、正在驶回车库、有SAL任务、TIMS保持或未停稳的列车不能通过此指令释放。
释放后的手动状态持久保存，SAL不会自动重新接管，也不会把它选为叫车候选。
此指令保留车辆段归属，重新纳管时无需重新创建列车。

## 手动交给SAL

1. 持有当前列车驾驶权，将运行方向的领车停在有效 `[SAL] depot` 停车点范围内。
2. 整列速度归零、观测完整且连续停稳3秒后，当前司机收到聊天按钮 `[确认SAL纳管]`。
3. 点击确认后，司机收到车辆段/停车位说明，需在30秒内自己输入 `/st release`，或点击 `[确认释放驾驶权]`。
4. STF明确释放同一驾驶权后产生一次性回执；SAL验证回执、库位和停稳状态，再经STA请求STF接管停车。完成后提示自动待命。

纳管成功时归属设为实际停车位所在车辆段。无须管理员预先执行 home；该操作不会直接发车或申请MA。
普通司机使用 `skyatolite.driver` 权限（默认允许）；线路编辑和 home 管理仍需 `skyatolite.admin`。

直接 `/st release` 而没有先确认纳管，不触发移管或新的纳管提示。离车、断线、换司机、列车移动、
离开库位或过期确认均不能代替明确移管。旧聊天按钮和旧驾驶权不能复用。
提示对每次连续停车只发送一次；按钮过期后可驶离停车点再重新停车。

已绑定home、没有真人驾驶权的新车仍可按原流程手推入位；有真人驾驶权的列车必须完成上述两步确认。
手动状态、处理过的释放回执在SAL状态文件内持久保存；未完成的确认不跨重启保留。

## STA契约与线程

`AutomaticTrainService.manualDrivers()` 发布不可变 train/driver/lease 快照；`manualReleases()` 只发布显式 `/st release`
成功后的 train/driver/lease/receipt/releasedAt 回执，不把司机消失、卸载或断线当作释放。
回执在STF驾驶权锁内先发布，再对外暴露无司机状态，避免无司机间隙被误认为可直接接管。

Message仍为私有6508，新增的两个Packet属于SKY_ATO私有编号：

| Packet | 接口 | 约束 |
| --- | --- | --- |
| 5117 | releaseStandby | 仅停车会话；完整停稳后在实体tick中转手动 |
| 5118 | acceptDepotHandover | 同一显式释放回执、1.5秒内、停稳与库位复核、无人驾驶；回执仅消费一次 |

SAL只处理线路、确认和提示，不操作列车实体。STF的移管提交在驾驶权锁下再检查回执及停稳，
不能与真人驾驶权同时取得。物理制动和驾驶模式变更仍由STF的实体tick执行。

## STF 5.0破坏性变更

旧STF牌子自动起停、巡航、站停、发车、自动spawn/destroy/property执行链及其轮询注册器已删除，
不提供默认关闭后重新启用的兼容开关。`/st property <train> mode automatic` 不再可用；请经SAL纳管。
旧自动模式不能靠存档或模板恢复执行权；旧自动存档按手动停稳状态加载。
不再读取 `automatic-signs.yml`，旧文件和世界中的牌子保留，但不执行自动驾驶动作。

STF保留列车实体、手动驾驶、物理运动、ATP、道岔执行和STA自动控制适配器。
STF的 switch/origin/balise/end 工务设备入口继续存在；运营 station、property、叫车和车辆段使用SAL牌子。
原有车站显示元数据不被删库，不再驱动自动列车。

删除旧功能对应的测试，保留独立的手动驾驶、制动、TIMS、ATP和轨道图回归。
新增连续停车计时、双重确认、驾驶权/确认码围栏、普通释放不纳管、断线/运动/超时撤销、
停车会话释放、一次性回执提交，以及旧ATO不再打包的测试。
