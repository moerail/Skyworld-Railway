# 纳管提示、通用途中折返与手动牵引 · SAL 0.8.0 / STF 5.1.4

**[新增／修改 · 2026-11-26]** 本版将出库接客和回库统一到分段机动寻路。修复 depot 纳管提示丢失、确认码不刷新，以及等待区块加载时手动牵引档被清回 P0 的问题。STA 2.9.2、STCS 4.3.6、PCC 2.6.4 保持兼容，无新增协议编号。

## depot 手动移管

~~SAL 要求速度不超过 0.000001，提示和确认码只尝试一次。~~ 现在使用与 STF 一致的 0.001 格/tick 停稳速度阈值，并保留完整车身、新鲜观测、TIMS、驾驶权及保护模式检查。自动提示仍要求车身任意部分覆盖已登记 depot，并连续停稳三秒；不要求列车中心对牌。

- 确认码生成和提示成功发送分别记录。发送前临时观测变化等导致未送达，会按至少一秒间隔重试；已送达的同一码不反复提示。
- 未确认码有效期仍为30秒；持续满足停车条件时，过期会更换新码。已确认但未在确认后30秒内释放驾驶权，也重新开始确认；旧码及排队的旧提示不能生效。
- 坐在车里保留实际驾驶权，执行 /sal handover 可以立即申请码；不满足条件时显示观测、车身、TIMS、保护状态、驾驶权或停车覆盖等原因。
- /sal handover 六位码 或点击确认后，仍须司机明确 /st release 才完成移交。普通释放、离座、断线均不自动视为同意。
- 纳管不会清除 TIMS、TR/PT、账本占用或授予 MA；STF 仍在提交时检查实际停稳、位置和 release 回执。

## 分段机动寻路

~~仅比较一直向前或原地换向一次再一直向前；不搜索途中折返。~~ 新规划器搜索有向 RailGraph 的合法通路，把换向作为显式动作，输出若干“行驶段＋段前换向”。跨工务线路名称不自动判为不可达，合法性仍取决于图的方向边、道岔通路和 STCS 许可。

例如：从库位出发 → 驶过道岔进入可容纳整列的股道 → 停稳 → 释放旧 MA 并确认 → 换向 → 申请新一段进路／MA → 到叫车站点。回库使用同一个规划器，最终目标仍按库位中心及允许偏移计算，不改为车头对牌。

### 几何与计算约束

- 按实际车厢位置重建整列长度与车头到车尾距离。折返后的车头是原车尾，不是原车头坐标简单反向。
- 允许整列跨越非分岔的应答器边界，但折返停车时，整列及两侧至少2格检查范围不得跨道岔／股道边界。规划目标另留0.25格停车余量。
- 使用唯一可确认的连续股道、显式反向边及合法道岔通路；短股道、缺反向边、未确认连接、占用或无法确认车身时，不强行折返。
- 搜索最多4次换向、8192个展开状态，每个行驶段最多256条不重复有向边。接客共用批次计算预算；回库每轮选择共用200ms预算。预算耗尽不会提交部分解；如果已找到完整合法的直达或原地换向方案，可以保留该完整方案，不再保证机动成本最优。尚无完整方案时可能需要更明确的线路设备或等待重算。
- 成本包括行驶距离和每次换向8秒估计；不是对真实到达时间的保证。现有接客时间上限、偏好车池、库位独占、整列空间和单端深处优先继续有效。
- 这不是无限制的任意地图可达性证明，也没有增加死锁自动解困。

### 执行与故障

每个行驶段分别经现有 STA 契约提交给 STCS；不会把含换向的整段轨迹当成一份 MA。到折返点后先制动停稳，复核完整车身、净空及预计新车头，再等待 STCS 确认旧 MA 已释放；随后向 STA 请求换向。取得新鲜 REVERSED 反馈并确认新车头符合下一段起点后，才启用下一段及申请新许可。

释放未确认、TIMS 保持、TR/PT、车身不明或净空不满足都不会执行换向。反馈或换向后定位持续10秒未确认则进入 FAULT 并保持制动。释放只处理车前许可，车身占用不清除。实际轨道变化仍触发原有依赖检查；途中暂时拥堵仍由 STCS 控制，不以自动排道岔撤销另一列车 MA。

运行中的机动计划不在重启后自动恢复：和既有任务一致，重启后进入 RECOVERY_REQUIRED 等待管理员确认；未提交叫车仍取消。运营线路的发布版和明确站停折返规则不因此改写。

## hotbar 手动牵引

原先 TrainMotionController 在 CHUNKS_LOADING 分支直接将 powerNotch 清成0，所以跨区块后 PCC 也会看到 P0/B0；制动档不受该赋值影响。现在保留司机选定的牵引、制动和换向器，只在执行层禁止牵引并施加原有保护制动。区块就绪且其他许可满足后，按当前手柄继续。

这不自动恢复被 TIMS、驾驶权丢失、MA释放或人工操作清除的牵引；也不解除 TR/PT。司机等待期间改为中立或制动，新输入仍优先，不会恢复旧 P 档。
