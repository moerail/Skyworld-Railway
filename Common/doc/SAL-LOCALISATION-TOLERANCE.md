# SAL同帧定位、有限容差与原始故障

**[修正 · SAL0.7.6 · 2026-11-26]** 回库库位复核、障碍保持、等待重新选位时维护原已接受进路的静默续租，避免超过1500ms心跳失效。复核默认2秒；车身暂不确定不再误报拓扑改变并立即丢目标。持续未知停为FAULT，真实空间／库位问题停稳后重选；状态显示具体原因并明确区分历史派车记录。 [详细说明](SAL-RETURN-RECHECK.md)

2026-11-26：SAL0.7.6 / PCC2.6.4，配套STA2.9.2 / STF5.1.2 / STCS4.3.5。

## 针对的报错

生产事件已记录：test2先取得可执行FS，约13秒后SAL报告`STA定位不确定：rail=693,70,-707`，之后STCS收回不可用MA，SAL进入SR_PENDING。该事件证明定位查询失败，不足以单独证明车辆实际走错分支。

上一版已解决把floor(entityY)误当railY的问题。本轮进一步修正：轨道方块坐标与查询方向必须来自**同一份STF物理遥测**。原来将缓存轨道坐标与更新的v8车辆方向混用，车辆刚转90°时可能查不到边。现在先用同帧railXYZ与motionXYZ查询STCS，再将当前实体位置连续投影到该边／实际相邻边，计算进度。静止遥测方向为零时才沿用当前车辆方向。不会按运营线路反推一个“应该在这里”的位置。

本轮不改STCS定位器、道岔规则、轨道图或ATP授权算法；不会因SAL放宽容差而把STCS拒绝的许可当作有效MA。

## 三种处理

| 情况 | SAL行为 |
| --- | --- |
| 定位与任务路径匹配 | 正常计算进度，行驶仍需有效MA、完整性和ATP条件 |
| 单次查询失败／边界短暂不匹配 | 当次立即发送零巡航、零剩余距离的制动意图；保留计划，最多复核默认2秒，不立即丢任务或申请SR |
| 持续不确定达到上限 | 保持制动，记录原始原因，进入原有PCC逐段SR恢复 |
| 两份独立观测确认另一分支，且已离开节点容差区 | 提前进入恢复，无须等满2秒；重复读取同一遥测时间不算第二份证据 |

在复核期间只续租已存在的进路，不新建路径、不扩大MA。确认恢复后继续原任务计划；如果STCS或车载ATP已独立进入TR/PT／不可用，SAL不能替它自动解除保护。必要时用管理员override退出SAL，再按正常手动规程处理。

端点容差只用于同一边上的计划范围和共享节点附近的边切换，并把进度限制在计划端点。它不是把平行股道、错误分支或其他世界吸附到目标线路的半径。超过端点范围仍需复核／恢复。

## 配置

位于SAL config.yml；既有配置缺键自动使用默认值。停服备份后修改并完整启动，不使用reload切运营状态。

```yaml
localisation:
  position-tolerance-blocks: 1.5
  endpoint-tolerance-blocks: 0.75
  confirmation-ms: 2000
```

| 参数 | 默认 | 有效范围 | 含义 |
| --- | --- | --- | --- |
| position-tolerance-blocks | 1.5格 | 0.25–2格，有限数 | 实体与图的最大三维投影误差；默认不比旧版放宽 |
| endpoint-tolerance-blocks | 0.75格 | 0–1格，有限数 | 节点／计划边界的进度匹配容差，内部按blocks-per-meter换算 |
| confirmation-ms | 2000ms | 100–10000ms整数 | 持续定位不确定进入恢复前的最长复核窗口，期间制动 |

无效配置拒绝启用并保留原状态文件，不默默接受无限容差。窗口遇到有效路径定位会清除；新一段计划不继承上一段的故障计时。重启仍按原有RECOVERY_REQUIRED处理，未确认的暂态不会直接恢复行车。

## 不再丢失故障原因

确认进入恢复时，在任务中持久保存原始故障及发生时间。`/sal status`和STA运营投影的reason会同时显示当前阶段与原始故障，进入“等待PCC批准SR”不会覆盖它。旧任务升级前没记录的原因无法追溯补造。

ROUTE_DEVIATION事件仍使用原编号／类型，增加失败阶段、图版本、实体坐标和计划边摘要。事件字段按STA既有256字符上限裁剪；任务原始原因最多2048字符。控制台仅在确认进入恢复时写一条，不逐帧刷定位日志。

PCC行车事件正文直接显示details.detail，悬停可见位置和阶段，作为纯文本渲染。提示改称“自动线路跟踪失效”，避免把一次定位失败直接描述成实际脱离线路。没有新增可执行控制端点。

## 生产测试步骤

1. 已在上一配套的用户仅替换SAL0.7.6和PCC2.6.4，保留STA2.9.2、STF5.1.2、STCS4.3.5。保留配置、SAL状态、列车和账本，PCC用Ctrl+F5刷新。
2. 现有恢复任务需明确处理。可`/sal override test2`，等完成后手动将车开回depot，重新确认纳管；不能把升级理解为自动恢复出库。
3. 先低速经过原出库段和坡道，观察有无“定位复核（保持制动）”。瞬时误差恢复后应保留原任务，不额外生成SR请求；MA/ATP仍可独立保持停车。
4. 若持续进入RECOVERY_SR，直接提供新版`/sal status`中的原始故障及PCC行车事件正文，不必再只截图“等待SR”。记录时间、列车UUID、五插件实际版本及线路发布版。
5. 不在生产线上人为扳错已锁道岔或拆轨来验证分支保护。离线测试覆盖了真正错误分支、不同图比例、重复观测、超时与重启原因保留。

本轮通过的是离线算法、契约、浏览器回归，不是生产坐标693/70/-707的实车验收。没有重启本地测试服，也没有代操作生产。
