# SAL回库复核与进路续租

**[修正 · SAL 0.7.7 / STCS 4.3.6 · 2026-11-26]** 双车回库保留已选路径和库位，临时咽喉交通由 STCS 限制/延长 MA，不再因其他运行列车经过就丢计划。自动排道岔不得撤销另一列车 MA；目的库位净空、停放车障碍及真实故障检查保留。 [新版回库规则](SAL-RETURN-TRAFFIC.md)

2026-11-26：SAL0.7.6，配套STA2.9.2 / STF5.1.2 / STCS4.3.5 / PCC2.6.4不变。

## 对应的问题

回库时出现“库位几何已改变”，并反复记录AUTOMATIC_ROUTE_UNAVAILABLE与重新ALLOCATED。代码确认有两个问题：

- 库位复核、障碍保持及等待新库位的分支，部分只发送了制动意图，没有发送原进路心跳；STCS自动进路心跳超过1500ms会失效。
- 一个布尔检查把库位缺失、边界不可用、中心不在股道、车长放不下、车身路径暂时无法计算都称为“库位几何已改变”。后者并不证明拓扑变化；立即丢目标重算会放大暂态波动。

库位边界构建没有读取道岔当前开向，正常转岔本身不应被认为是库位拓扑变化。本修复不移除STCS图依赖、实际断路、锁闭或占用保护。

## 新行为

回库复核失败仍立即制动，同时对**已经接受的、当前版本相符的进路**继续静默续租，不因制动而饿死1500ms心跳。等待重新分配库位、实际其他车身阻挡时也维护原租约。租约已失效、版本不符或控制权不符时不伪造续租成功，也不以续租建立新进路。

默认复核2000ms，期间保留原停车目标和计划：

| 检查结果 | 处理 |
| --- | --- |
| 复核恢复 | 沿原目标继续，仍须有有效MA及ATP条件 |
| 车身路径暂不确定 | 制动复核；持续不确定且停稳后进入FAULT，请检查或override，不把它当作拓扑变化不断重选 |
| 真实库位／边界／停车中心变化，或当前车长放不下 | 制动；窗口结束且停稳后才重选库位 |
| 仍在移动 | 持续制动等待，不能在移动中更换目标 |

空间校验仍按完整车身长度、中心位置、库位边界和停车余量进行。没有新增“忽略车长”的容差，也不缩小安全间隔。重新选择后如无合法库位，继续保持停车。

`depot.recheck-ms`默认2000，允许100–10000整数。旧配置缺键使用默认值，无效值拒绝启用。更新配置需完整启动，不reload运营状态。

## 可见的原因

`/sal status`和PCC运营原因会区分：停车目标缺失、库位不可用及原因、中心不在登记股道、车身路径未知，以及空间不足时的车长／中心／边界／余量。复核问题写入`lastReturnIssue`，确认任务结束时控制台记录列车、停车位和最后一次回库复核原因。

只在实际问题时发回库警告，同一任务最多每5秒一条，不逐帧刷屏。持续BODY_UNKNOWN后转FAULT，其后MA正常撤回是保护结果，不再自动反复分配新MA。

`/sal status`活动任务与历史派车记录之间新增明确标题。显示“没有运行或待派任务”时，随后ASSIGNED只是历史，不代表尚有活动任务；也不能单凭它反推之前运行是否顺利。

## 生产测试

1. 已安装上一配套仅换SAL0.7.6，保留数据和账本；不需要更换PCC或改Token。
2. 明确恢复／override处理现有任务后，测试一圈回库，重点经过道岔和坡道。
3. 如出现复核，查看新版/sal status：不应只剩笼统“拓扑改变”，应有准确类别和数值。
4. 短暂复核恢复后应继续原目标；制动复核期间不应仅因漏心跳而超过1500ms后丢失原MA。真正图变化、故障或STCS拒绝仍会保持停车。
5. 长时间车身未知应停为FAULT而非无限重选。空间真实不足应在停稳后换位，不能强挤原位。
6. 到达后检查实际停车与控制台任务结束记录。保留发生时间、列车UUID、kind/detail、图版本及五插件版本，便于确认生产现场是否还有其他原因。

本轮只离线测试，不代操作生产或启动本地测试服。生产日志能表明MA反复失效／重分配，但尚不足以证明每次停顿只有上述一种原因。
