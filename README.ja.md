# SkyRail Suite

[ホーム](README.md) | [中文](README.zh.md) | [English](README.en.md) | [Nederlands](README.nl.md) | [Français](README.fr.md) | **日本語**

**日本語完全版。本書だけで読めるため、補助文書は不要です。**

Minecraft / Folia 向けの列車運転、鉄道施設、影方式列車制御および運行指令表示の一式です。SkyRail Suite は SkyTrain Suite 開発系統の新しいリポジトリ名です。実行時の拡張機能名、指令、データ保存先は従来どおりです。

本書は **2026 年 9 月 13 日現在の手元のソースコード**に基づき、2026 年 9 月 14 日に日本語版を作成したものです。サーバー管理者、運転士、線路建設者および拡張機能開発者を対象とします。将来案として論じられた事項が実装済みであるとは限りません。

> **開発版の制限：** 現在、本一式は影方式 MA/EoA 情報をオンラインで算出・割当・表示しますが、ATP はそれに基づいて制動を掛けません。要求の受理、PCC 上での空き表示、RBC オンライン表示のいずれも、安全な進行を保証するものではありません。運転士喪失時の非常制動、手動非常制動、RECOVERING 中の制動保持は、これとは別に実働する車両制御機能です。

**TrainCarts 開発者へ：** TrainCarts は標識インターフェースおよび運用手順の一部に対する参考実装です。本書は TrainCarts との完全互換、同等の運動特性、または全 TC 拡張との互換性を主張しません。STF の `switch` は TC の `switcher` ではありません。本一式は TC も BKCommonLib も必要とせず、二つの制御機能で同じトロッコを同時に制御してはなりません。

## 1. 目的と構成要素

SkyTrain Suite は Minecraft を対話可能な鉄道運転環境として用います。利用者が実物の線路を敷設してトロッコ列車編成を運転し、拡張機能が列車の運動と鉄道網の識別を担い、位置・占有・走行許可を運転台と運行指令画面に表示します。

本計画では、運転権、資源占有、競合進路、Movement Authority（MA、走行許可）、End of Authority（EoA、走行許可終端）、不確実な観測の凍結保持を明示的に扱います。ETCS の責務分離思想を参考にしていますが、**SUBSET-026 準拠装置でも、認証済み連動装置でも、実在鉄道用の保安装置でもありません**。

| 構成要素 | 現行版 | 主な責務 |
| --- | --- | --- |
| SkyTrainFolia / STF | `2.1.0-alpha.7` | 列車編成、運動と曲線通過、運転権、力行・制動、車両諸元、標識、実体分岐器の転換、運転台表示および音響 |
| STCS | `2.2.0-alpha.1` | 鉄道施設、有向 RailGraph、線路里程、位置標定、占有保持台帳、影方式 MA/EoA および局所的な分岐器検査 |
| SkyworldTrainAPI / STA | `0.8.0` | 拡張機能間の版付き契約、遠隔測定、編成車両観測、運転台状態、走行許可および事象交換 |
| SkyPCC | `0.8.1` | ウェブ式配線略図、列車・施設検査、占有・予約表示、事象欄および認証付き分岐器制御 |

```text
Minecraft 利用者 / トロッコ / 線路 / 赤石回路
                         |
                        STF   実体運動、運転および転換
                         |
                        STA   契約、遠隔測定および事象
                         |
                       STCS   図、位置標定、占有、影方式 MA
                         |
                       SkyPCC ウェブ監視および操作画面
```

これは責務の概略であり、すべての呼出しが必ず図の順に直列転送されることを示しません。閲覧器上の位置補間は保安用位置情報ではなく、どの線路資源を許可できるかをウェブ側が決めるものでもありません。

### 実装済み範囲と計画範囲

| 範囲 | 現状 |
| --- | --- |
| 手動運転、明示的な運転権、運転士喪失時の非常制動 | 実装済み。乗車のたびに運転権の取得が必要 |
| 列車編成、線路座標に基づく運動、高速時の表示適応 | 実装済み。高速運転、領域跨ぎ、第三者拡張との組合せは実サーバーでの検証が必要 |
| 駅における擬似自動運転 | 車両の力行・制動段を用いる MVP。完全な ATO ではない |
| 図、線区帰属、里程、占有保持 | 実装済み。時間切れや領域読込み解除のみでは開通を証明できない |
| オンライン MA/EoA と空間予約 | 影方式として実装。ATP 制動なし |
| ウェブ分岐器制御 | 認証、局所検査、非同期 PENDING を実装済み |
| 車上速度照査曲線および速度超過/EoA に対する ATP 制動介入 | 未実装 |
| 完全な行先別自動進路構成と時刻表 ATO | 完全な体系としては未実装。route 属性は進路開通を意味しない |

| 独立した SIR、SkyCBI、Python RBC 業務 | 構想段階であり、現行の導入構成要素ではない |

## 2. 導入と更新

### 動作環境

- 現行の適合基準は **Shiroha / Folia 26.2 および Java 25** です。本一式で検証済みの同系列サーバー版を使用してください。
- STF には版に依存する実体運動・表示適合処理があります。`folia-supported: true` は全 Folia 版との互換を保証せず、`api-version: 1.13` も Minecraft 1.13 で動くことを約束するものではありません。
- PCC は通常のウェブ閲覧器で動作し、利用者側への改造導入を要しません。
- TC / BKCommonLib は必須ではありません。複数の列車制御拡張で同じトロッコを重複制御しないでください。

### 初回導入

1. 世界データと `plugins` 一式を複製保存し、まず試験サーバーで確認します。
2. サーバーを停止し、以下の四つの JAR を `plugins` に置き、同名拡張機能の旧 JAR を取り除きます。
3. 一度完全起動して既定設定を生成し、四つすべてが正常に有効化されたことを確認します。
4. 停止して設定を調整し、再び完全起動します。第三者の熱交換機能で拡張機能を動的に解除・交換しないでください。
5. ゲーム内で `/st version` と `/stcs status` を実行し、サーバー機上の閲覧器で `http://127.0.0.1:8765/` を開きます。

現行の導入ファイル：

```text
SkyTrainFolia-2.1.0-alpha.7.jar
STCS-2.2.0-alpha.1.jar
SkyworldTrainAPI-0.8.0.jar
SkyPCC-0.8.1.jar
```

STF/STCS は STA を任意依存として宣言していますが、全機能を使う場合は四つを一組で導入してください。PCC は STCS と STA を必須とします。STF 単独では、完全な線路図、走行許可、運行指令表示の機能を提供しません。

### 更新規則

- 特に STA 契約が変わる版では、互換性のある一組を更新してください。`artifacts` 内の歴代 JAR を全部導入してはいけません。
- 既存設定とデータを保持し、現行の既定設定と比較して新しい設定項目を統合します。既存設定には、欠落項目が自動追記されるとは限りません。
- `/st reload` は設定だけでなく列車データも再読込みします。**先に全列車を停止してください。** 音響だけの再読込みではありません。
- STCS/PCC の設定は完全再起動で反映します。本書に存在しない `/stcs reload` や `/skypcc reload` を想定しないでください。
- 位相構造や図認識規則を変更した後は、対象線路を読み込ませてから `/stcs rebuild` を実行します。ウェブや音響だけの更新なら通常は再構築不要です。
- ウェブ更新後は強制再読込みを行います。旧版へ戻す場合は、同一時点の JAR、世界、データを一組で復元し、新旧の台帳を混用しないでください。

## 3. 権限と言語

| 権限 | 既定 | 主な用途 |
| --- | --- | --- |
| `skytrain.use` | 全員 | 基本照会、個人言語・単位、通常の運転指令 |
| `skytrain.admin` | OP | 列車編成、属性、雛形、遠隔運転、分岐器管理、保存・再読込み |
| `stcs.use` | 全員 | 近傍施設照会、図状態 |
| `stcs.ma` | 全員 | 運転士による MA 要求・解放。有効な運転権と許容状態も必要 |
| `stcs.admin` | OP | 施設登録、再構築・書出し、占有・MA 診断、防護状態、分岐器管理 |

権限は運転権ではありません。`stcs.ma` を持っていても、別の運転士に代わって MA を要求できません。防護状態の管理では、管理者自身が対象列車に着席している必要があります。位置依存の指令はすべて操作卓から実行できるわけではありません。

PCC の HTTP 制御は別個の認証票、ループバック接続および同一生成元検査を用い、Minecraft の OP 権限を継承しません。一般旅客に制御認証票を渡さないでください。

```text
/st lang jp
/st lang ja
/st lang zh
/st lang fr
/st help 2 jp
/stcs help 1 fr
/sta version ja
/skypcc help
```

`ja` と `jp` はいずれも日本語を選択します。四つの根指令はいずれも `help` と `version` に対応します。運転台表示、防護、MA 表示は STF の利用者別言語設定に従います。一部の旧管理・診断文は中国語または英語のままです。**蘭語文書があっても、ゲーム内言語に蘭語が追加されるわけではありません。**

PCC の言語選択は閲覧器に独立して保存され、ゲーム内言語には影響しません。

## 4. 最初の手動運転列車

平坦で読込み済み、かつ他列車のない試験線路に数両のトロッコを置きます。隣接線の車両を編成に含めないよう、小さい探索半径を指定します。

管理者が実行：

```text
/st scan 6
/st create demo 6
/st info demo
/st property demo trainnumber T001
/st property demo mode manual
```

車内に乗り、次を実行：

```text
/st lang jp
/st drive
/st forward
/p1
/n
/b3
/b7
```

- `P1..P4` は力行段、`B1..B7` は常用制動段、`EB` は非常制動です。
- `/n` は主幹制御器の中立、`/st neutral` は逆転器の中立であり、両者は異なります。
- 逆転には低速・停止検査があります。強制逆転を通常の制動代わりにしてはいけません。
- 乗り直すたびに `/st drive` で運転権を取得します。他の運転指令が暗黙に運転権を取得することはありません。
- 降車、切断、死亡、列車変更、運転席実体の消失時は、運転権を取消し、力行を零にして非常制動を掛けます。他の旅客に自動で運転権を渡しません。
- `/st release` は明示的に運転権を解放し、非常制動を掛けます。自動運転には、さらに完全停止と明示的な `mode auto` 設定が必要です。

### 快捷欄

`/st hotbar` を有効にする前に、快捷欄の **第 5 枠**を選択してください。有効化そのものは N を入力せず、既存の制動も解除しません。その後の枠変更で段位を入力します。

| 枠 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 段位 | B7 | B5 | B3 | B1 | N | P1 | P2 | P3 | P4 |

再度 `/st hotbar` を実行して解除するときは、第 5 枠である必要はありません。`/st cab` で図形運転台を開くこともできます。どちらも先に `/st drive` が必要です。

### STF 管理者指令

| 指令 | 用途 |
| --- | --- |
| `/st connect [radius]` | 近傍トロッコの連結 |
| `/st create <name> [radius]` | 列車編成の作成 |
| `/st append <train> [radius]` | 車両追加。初期の列車制御試験では固定編成を推奨 |
| `/st unlink` | 最寄りトロッコの結付け解除 |
| `/st remove <train>` | 列車定義を削除。STCS 阻塞を消す近道ではない |
| `/st start <train> [speed]`、`/st stop <train>` | 旧来の目標速度制御・停止。MA 承認ではない |
| `/st reverse <train>` | 逆転。停止検査あり |
| `/st speed <train> <speed>`、`/st maxspeed <train> <speed>` | 目標速度・列車上限。単位は block/tick |
| `/st spacing <train> <spacing>` | 車両間隔。全体の密着編成設定による制限あり |
| `/st property <train> <key> [value]` | 値なしで照会、値ありで設定 |
| `/st tag <train> add\|remove\|list [tag]` | 標札 |
| `/st owner <train> add\|remove\|list [player]` | 所有者付帯情報 |
| `/st route <train> set\|add\|clear\|list [destination...]` | 行先一覧。完全な自動進路構成ではない |
| `/st savedtrain list` | 雛形一覧 |
| `/st savedtrain save <train> <template>` | 雛形保存 |
| `/st savedtrain spawn <template> [train]` | 利用者近傍に雛形列車を生成 |
| `/st switch list`、`/st switch scan [radius]` | 分岐器一覧・読込み済み領域探索。既定 32、最大 128 ブロック |
| `/st switch info`、`/st switch set straight\|diverging` | 8 ブロック以内の最寄り分岐器を照会・転換要求 |
| `/st switch remove`、`/st switch cleanup` | 最寄り定義削除・無効登録整理。`remove` は世界内ブロックを残す |
| `/st balise list`、`/st origin list`、`/st end list` | 施設一覧 |
| `/st clearkm <line>` | 線路里程標定を消去。占有は消さない |
| `/st admin release\|p1..p4\|b1..b7\|n\|eb <train>` | 明示的な遠隔管理運転 |
| `/st syncstatus` | 表示同期診断 |
| `/st save`、`/st reload` | 保存・再読込み。事前に全列車を停止 |

属性指令は `property <train> get <key>` および `property <train> set <key> <value>` にも対応します。本書では短い形式を用います。

### STCS

| 指令 | 権限・意味 |
| --- | --- |
| `/stcs help [page] [language]`、`/stcs version [language]` | 説明・版 |
| `/stcs inspect` | `stcs.use`。3 ブロック以内の標識 |
| `/stcs status` | `stcs.use`。図の節点・辺・改訂。列車の ATP 状態ではない |
| `/stcs ma demand` | `stcs.ma` と現運転士。影方式 MA を要求 |
| `/stcs ma release` | `stcs.ma` と現運転士。前方予約を解放し、車体占有は解放しない |
| `/stcs ma status` | `stcs.admin`。走行許可・阻止理由診断 |
| `/stcs admin status` | `stcs.admin`。乗車中列車の防護状態 |
| `/stcs admin isolate true\|false` | 列車制御隔離 |
| `/stcs admin bypass true\|false` | 監視迂回 |
| `/stcs admin shadow true\|false` | 影方式試験 |
| `/stcs occupancy [train-name\|uuid]` | `stcs.admin`。保持占有・車両観測 |
| `/stcs rebuild` | `stcs.admin`。登録施設から図を再構築 |
| `/stcs export` | `stcs.admin`。現行図を書出し。再探索ではない |
| `/stcs switch info` | `stcs.use`。8 ブロック以内の最寄り分岐器 |
| `/stcs switch change` | `stcs.admin`。近傍分岐器を転換 |

利用者指令は **`request` ではなく `demand`** です。内部事象名は `MA_REQUESTED` の場合があります。`/sta` と `/skypcc` は主に説明と版を示すもので、別系統の運転指令ではありません。

## 6. 車両諸元と属性

### サーバー共通車両諸元

`plugins/SkyTrainFolia/config.yml`：

```yaml
settings:
  default-vehicle-profile: minecraft-comfort
  server-speed-limit-kmh: 420.0
```

ファイルは `plugins/SkyTrainFolia/vehicles/<id>.yml` にあります。

| ID | 参照車両 |
| --- | --- |
| `crh380b` | CRH380B |
| `cr400bf` | CR400BF |
| `keikyu-n1000` | 京急新1000形 |
| `minecraft-comfort` | ゲーム向け架空諸元 |

実車諸元は調整用の近似値であり、認証された性能資料ではありません。現行の選択は **サーバー全体で共通**です。列車別の `/st property <train> profile ...` 指令はありません。

一つの諸元は基準列車全体を表します。Minecraft 上のトロッコ両数に応じて、基準質量や性能が自動比例するわけではありません。一方、実編成長は占有、駅停止、分岐通過後に必要な収容長に影響します。

| 諸元項目 | 効果 |
| --- | --- |
| `physics-mode` | 運動模型。同梱諸元は `force` を使用 |
| `mass-tonnes` | 基準列車全体の質量 |
| `max-speed-kmh` | 車両上限。力行で到達できる保証ではない |
| `traction.acceleration-mps2.p1` から `p4` | 走行抵抗控除前の低速時総力行加速度 |
| `traction.base-speed-kmh` | 力行曲線の基底速度 |
| `traction.field-weakening-speed-kmh`、`minimum-ratio` | 高速域の力行低減・最小比率 |
| `brake.deceleration-mps2.b1` から `b7` | 常用制動の総減速度 |
| `brake.emergency-mps2` | 非常制動の寄与分 |
| `resistance.rolling-mps2` | 転がり抵抗 |
| `resistance.air-mps2-at-100-kmh` | 100 km/h 時の空気抵抗基準。速度の二乗に比例 |
| `resistance.grade-mps2` | 勾配加速度係数 |
| `control.direction-change-speed-kmh` | 逆転許容の低速閾値 |
| `automatic.*` | 旧目標速度制御器の諸元。駅の段位制御全体ではない |

`drive-power-acceleration-p1` など旧来の分散項目は、現行の車両諸元編集方式ではありません。編集前に複製保存し、再読込み前に全列車を止めるか、停止中に編集して再起動してください。

### 130 km/h 制限が残る理由

車両上限、サーバー上限、列車別に保存された `maxspeed` は、いずれも速度を制限します。既定の車両諸元を変えても、既存列車の上限は消えません。

公称縮尺 1 ブロック = 1 m、20 TPS では、`km/h = block/tick × 72` です。

```text
/st property demo maxspeed
/st maxspeed demo 5
```

ここで `5` は 360 km/h を意味し、5 km/h や文字列 `5kmh` ではありません。これより低い車両・サーバー上限は引き続き適用され、力行と抵抗の釣合いで上限に届かない場合もあります。個人表示単位は指令の解釈を変えません。

### 列車識別と列車番号

```text
/st property demo name test01
/st property test01 displayname Test Train
/st property test01 trainnumber G001
/st property test01 trainnumber
/st property test01 trainnumber clear
/st property test01 mode auto
/st property test01 pushable true
```

- `name` は管理対象列車を指令中で識別します。改名後は新しい名称を使います。
- `trainnumber` は別個の列車番号です。先頭の零を保持し、最大 32 文字、制御文字と `|` は使用不可、重複は禁止されません。`clear` または `-` で消去します。
- `displayname` は表示用付帯情報で、内部 UUID ではありません。
- その他の属性：`destination`、`collision`、`playersenter`、`playersexit`、`pickupitems`、`invincible`、`allowplayertake`、`requirepoweredcart`、`sound`、`keepchunksloaded`、`gravity`、`friction`、`waitticks`、`speed`、`maxspeed`、`spacing`。
- `pushable=true` だけでは不十分です。運転士の存在、未解放の手動介入、運転状態によって押込みが阻止される場合があります。`/st info` を確認してください。
- 所有者・標札・進路の付帯情報は、完全な進路制御、運行指令、所有者別利用制限を意味しません。

## 7. 線区と分岐器の建設

### 物理位相構造と線区帰属

RailGraph は節点、接続口、許容遷移、有向辺、幾何形状を保存します。線名と里程は注記であり、接続されたすべての分岐器を越えて無制限に伝播させる情報ではありません。

- `test_up`、`test_down` のような一意の線名を、対象地上子で一貫して用いてください。
- Origin/End は線区帰属を区切りますが、物理的な線路終端である必要はありません。その先の線路も物理的接続を保つべきです。
- 線名のない側線地上子は、本線名を無制限に伝播させずに側線を標示します。
- 同じ線名付き標識間に複数経路がある場合、意図する本線側分岐に線名付き地上子を追加します。分岐器の現在開通方向は恒久的な線区帰属ではありません。
- 里程不明は不明のままです。別標識に近いだけでは推定できません。

### 四行式 STCS 標識

特に複線区間では、対象線路との対応が明確な位置に標識を設置します。

起点：

```text
[STCS]
origin
test_up
right
```

本線地上子：

```text
[STCS]
balise
test_up
0010
```

終点：

```text
[STCS]
end
test_up
right
```

第 3 行を空欄にした側線地上子：

```text
[STCS]
balise

5010
```

Origin の第 4 行は線区の正方向へ、End の第 4 行は線区外方へ向け、線区内方はその反対です。相対方向は標識面に対して解釈し、PCC 画面上の左右ではありません。`signal` は節点として登録できますが、信号現示による ATP が実装済みであることを意味しません。

### STF 分岐器標識

STCS は登録済み STF 分岐器を取り込み、すべての曲線線路を取り込むわけではありません。登録は大文字小文字を区別せず `[stf]`、`[+stf]`、`[SkyTrain]`、`[+SkyTrain]` を認識します。赤石作動と施設の存在は別問題であり、`+` の追加は一般的な欠落辺修正にはなりません。

既存の正面取付配置の例：

```text
[SkyTrain]
switch
fl
S01
```

第 4 行は分岐器名で、UUID が識別子として残ります。**STF の `switch` は TC の `switcher` ではありません。**

壁面標識は既存の側面・線路下配置に対応します。正面配置 `fl/fr` では、標識の取付けブロックから二つ上に転換中心線路を置きます。天井吊下標識では、標識 → 上の支持ブロック → さらに上の転換中心線路とし、斜めではなく東西南北に揃えます。中心には通常の転換可能線路を用います。結付けた梃子は分岐器転換に追随し、隣接赤石ブロックへ通知します。複雑な回路はゲーム内で検証してください。

建設後：

```text
/st switch scan 32
/st switch list
/stcs inspect
/stcs rebuild
/stcs status
/stcs export
```

再構築は登録施設を起点とし、世界全体を無制限に探索するものではありません。WorldEdit 使用後は登録を確認してください。既定では読込み済み区画だけを探索し、探索不完全時は既存位相を保持します。未観測線路を無から再構築することはできません。

```yaml
scan:
  max-distance-meters: 256.0
  blocks-per-meter: 1.0
  marker-rail-search-radius: 3.0
  only-loaded-chunks: true
graph:
  file: railgraph.json
  pretty-print: true
```

この探索距離は MA 前方探索距離ではありません。長い区間には適切な標識または大きい探索上限が必要です。STF/STCS の距離縮尺は通常 1 ブロック毎メートルで統一してください。

## 8. 自動標識と駅停車

station/spawn/destroy 画面は TC に着想を得た慣例に従います。線路との対応付けは、任意の近傍球ではなく、線路下の標識列および取付け関係に基づきます。**これらの形式への対応は、TC の全式、遠隔標識、拡張との完全互換を意味しません。**

手動運転中の列車を station/destroy が自動介入することはありません。列車を止め、運転士が `/st release` を実行してから、明示的に `/st property <train> mode auto` を設定します。ISOLATED、RECOVERING、未解放の手動介入も自動処理を阻止します。

一般的な先頭行：`[stf]` は赤石作動、`[+stf]` は常時有効、`[!stf]` は反転、`[-stf]` は無効です。解析器は立上り・立下り縁形式にも対応しますが、実際の発動は動作種別によります。

### 駅

```text
[+stf]
station
5
continue 40kmh
```

| 行 | 意味 |
| --- | --- |
| 1 | 先頭行・作動条件 |
| 2 | station。対応する発進距離・時間・加速度、停止位置補正を任意指定可 |
| 3 | 停車時分。単独数値は秒。`5s`、`100t`、`00:05` 形式にも対応 |
| 4 | 方向・速度。例：`continue 40kmh`、`reverse 0.4`。単位なしは block/tick |

運転権解放済み、自動、押込み可能な列車は駅へ押し込まれ、その後発車できます。遠方からの接近通知には、利用可能な STA/STCS 線区・駅照会が必要です。標識上で停車しても、事前検知が働いた証明にはなりません。

MVP は車両段位を使用します。発車時は高い力行段、目標速度付近では N/P1 調整、接近時は段階的に弱める制動、停止時は B7 です。瞬時の速度設定でも、全車両諸元・駅間隔に対する停止精度保証でもありません。

STF の `settings.station-look-ahead-blocks` は既定 8192、`station-launch-speed` は 0.4 block/tick です。最終停止位置合わせには別の諸元があります。これらは STCS の MA 前方探索とは独立しています。初めは広い駅間隔と低速で試験してください。

### 列車生成と撤去

```text
[stf]
spawn 0.0
mmm

```

制御された赤石入力で通常トロッコ三両を生成します。第 2 行は `spawn [velocity] [interval]` を受け付け、間隔は `00:30` などで指定します。第 3・4 行は連結して生成形式になります。基本車種記号は `m` 普通、`s` 箱付き、`p` 動力、`h` 漏斗、`t` TNT で、対応する雛形形式も使えます。初期試験では TNT を用いないでください。

自動生成用雛形は、明示的に auto 状態で保存する必要があります。無防護線路へ列車を連続生成しないでください。

```text
[+stf]
destroy


```

destroy は実体を本当に削除します。複製保存済みの別線で試験し、手動運転列車を削除しないことを確認してください。まず駅処理を検証し、その後 spawn/destroy を別々に試験します。

## 9. 影方式 MA と防護状態

| 用語 | 本書での意味 |
| --- | --- |
| MA / Movement Authority | 許容された有向経路に沿う影方式走行許可 |
| EoA / End of Authority | 現在の走行許可終端。必ずしも線区終端ではない |
| 残距離 | EoA までの経路上距離。直線距離ではない |
| 占有 | 車両観測・保持根拠から線路使用中と判断された状態 |
| 予約 | 前方の影方式資源確保。認証済み進路鎖錠ではない |
| RBC 回線 | 影方式情報通信路の状態。無線 RBC や実効 ATP の証明ではない |

### 運転士の手順

1. 位相構造、分岐器開通方向、位置標定および実際の試験進路を確認します。
2. 乗車して `/st drive` を実行し、停止後、要求可能な防護状態で進行方向を選びます。
3. `/stcs ma demand` を実行し、要求受付だけでなく、割当結果・理由を確認します。
4. 運転士の BossBar は MA 残距離、運転台表示は EoA の線区・里程、PCC は予約区間を示します。
5. 速度と停止は手動で制御します。`/stcs ma release` は前方予約を解放します。

無人列車は新しい MA を能動的に取得しません。運転士がいる停止列車と無人列車は異なります。MA 解放は車体占有を消さず、停止指令でもありません。

### 状態機械

| 状態 | MA・通信路 | 実働動作 |
| --- | --- | --- |
| SHADOW | 影方式要求・認識を許容 | MA・速度に対する ATP 介入なし |
| BYPASS | 通信路を保持。影方式 MA の保持・要求が可能 | 監視迂回。通信隔離ではない |
| ISOLATED | 新規要求を拒否し、車上制御通信路を隔離 | 読取り専用里程・STA 遠隔測定は保持。自動標識は無効 |
| RECOVERING | 新たな有効車上 MA なし | 制動保持、力行拒否、次状態の明示選択が必要 |

状態は列車データに保存されます。該当切替を `false` にすると RECOVERING に入ります。対象を `true` にするには、RECOVERING、編成全体の新鮮で完全な観測、停止が必要です。高速走行中に単純切替はできません。

対象列車に着席した管理者の例：

```text
/stcs admin shadow false
/stcs admin status
```

全編成停止後：

```text
/stcs admin bypass true
```

戻すには `bypass false`、停止、`shadow true` の順にします。状態変更は力行を消去して制動を掛けますが、自動発車しません。隔離後も地上側に残る予約・根拠は、車上で使用可能な MA でも延長根拠でもありません。

### 三つの距離設定

STCS 設定：

```yaml
ma:
  enabled: true
  look-ahead-meters: 600.0
  lock-distance-meters: 150.0
  max-authority-distance-meters: 300.0
  margin-meters: 2.0
```

| 項目 | 意味 |
| --- | --- |
| `look-ahead-meters` | 探索上限。見つけた全区間を予約するわけではない |
| `lock-distance-meters` | 影方式 MA が分岐器を越え得る接近範囲。遠方では分岐器手前に止まり、物理鎖錠を証明しない |
| `max-authority-distance-meters` | 実際の許可距離上限。前方探索上限にも制限される |
| `margin-meters` | 障害・競合手前の余裕。完全な制動距離ではない |

旧 `ma.horizon-meters` は、新項目欠落時の互換既定値を提供します。新規設定では三項目を明示してください。STF の `switch-approach-distance`、駅前方探索、BossBar 尺度はそれぞれ別設定です。

### 続行列車、並行進路、分岐部

空間 MA は地上子間の辺全体だけを確保するのではなく、物理線路セルと辺内区間を用います。反対向きの有向辺は同じ物理資源を共有します。

- 続行列車は常に直前の地上子ではなく、先行列車の占有・予約境界で制限されるべきです。
- 共用資源も競合もない並行進路は、近接のみを理由に駅咽喉部全体を鎖錠せず、同時に成立すべきです。
- 分岐器の非開通側が自動的に列車車体占有になってはいけません。
- 駅咽喉部へ進入する前に、進出側に全編成の収容長が必要です。不足時は進入手前で待ちます。
- 図・分岐器の状態不明、車両欠落、保持根拠は引き続き割当を阻止できます。外観だけを根拠に検査を迂回してはいけません。

車体写像と非同期整合は保守的ですが、列車完全性や車両限界通過範囲を証明するものではありません。実装は経路上を 1/4 ブロック間隔で障害探索しつつ、物理線路セル資源を割り当てます。これはブロック規模の影方式割当であり、認証済みの連続移動閉塞 ATP ではありません。予約は許可区間で終わります。共用する分岐器セルにより、非開通側の短い端部が着色されても、その分岐全体を予約したことにはなりません。

資源識別子は `cell@world:x:y:z` 形式です。旧来の辺全体占有記録は、完全で新しい観測に置き換わるまで保守的に阻塞を続けます。読込み解除、再起動、車両欠落、図不一致だけでは根拠を消去しません。このため旧記録を持つオフライン列車が広い範囲を阻塞する場合があります。新台帳と対応する複製保存なしに、古い版へ戻してはいけません。

## 10. SkyPCC ウェブ画面

```yaml
web:
  enabled: true
  bind-address: 127.0.0.1
  port: 8765
  control-enabled: false
  control-token: ''
  update-mode: auto
  poll-interval-millis: 1000
  sse-keepalive-seconds: 15
```

サーバー機上で `http://127.0.0.1:8765/` を開きます。別の計算機では、この番地はその計算機自身を指し、サーバーではありません。遠隔制御には SSH ローカルトンネルを使います。業務を公衆網に直接公開しても安全対策にはなりません。

### 表示

- 中国語・英語・仏語・日本語、明暗配色、同梱の昼夜標章。
- 線区選別、拡大縮小、全体表示、文字倍率。
- 位置標定待ちの列車も一覧に残ります。保持項目は新鮮な位置ではありません。
- 配線図表記：`<列車番号> | <列車名> | <速度> km/h`。番号なしは代替記号。
- 列車検査および視点追尾・解除：ATP 状態、MA/EoA、理由、方向、逆転器、主幹制御器、運転士、里程、辺、データ経過時間。
- 分岐器名は黄色地に黒太字。矢印は別表示で、直進側は紫、分岐側は橙黄。
- 地上子、分岐器、辺を選択して施設を検査できます。確定した本線里程を表示し、それ以外は側線里程を捏造せず、隣接する図節点・接続口からの距離を示します。
- 分岐器状態は受信時点の写しであり、閲覧器が行った新鮮な物理検証ではありません。
- 占有、凍結・不確実、影方式予約、未割当の区間を別色で表示します。灰色・未割当は開通の証明ではありません。
- 運転記録欄は重要度選別、折畳み、上方向展開に対応します。

### 分岐器制御

`control-enabled` を有効にし、**32 文字以上**の私的な無作為認証票を設定して再起動します。ウェブ制御画面から入力し、URL、画面画像、公開記録に含めないでください。

分岐器を選び、検査後に転換を確認します。要求には図改訂、識別子、予期状態・目標状態、位置が含まれます。STCS が局所検査し、STF が転換します。

- 無関係な遠方列車は自動的に要求を阻止しませんが、局所占有、予約競合、不確実性、状態・位置不一致は阻止できます。
- 未読込み位置は PENDING となり、非同期読込み後、所有領域上で再検証する場合があります。PENDING は成功ではなく、進行許可に用いてはいけません。
- 正しい認証票だけでは足りず、ループバックと同一生成元の検査も適用されます。
- 公開読取り専用表示には別の利用制限を設けるべきです。監視権限と制御資格は別問題です。

### 事象

事象には、運転権の取得・解放・喪失、分岐器転換、割出し疑い、非常制動投入、MA 要求・解放、ATP 状態変更が含まれます。状態変更事象は操作者と新旧状態を示します。管理者である操作者が運転士とは限りません。

STA は既定で現接続中の最新 500 事象を保持するだけで、恒久監査記録ではありません。平滑な MA 更新がすべて事象になるわけではありません。割出し疑いは、故障原因を完全に証明した診断ではありません。

## 11. 音響と運転台表示

MA BossBar は運転士だけに表示されます。STF の `settings.cab-ma-bar-range-meters` は既定 300 m で、棒尺度だけに影響し、本文は実距離を示します。側欄の ATP 速度上限は未実装の仮表示であり、既存の速度照査曲線ではありません。

### MA 音響設定

STF 設定の `settings` 配下ではなく、**最上位**に置きます。

```yaml
ma-sounds:
  enabled: true
  granted:
    enabled: true
    sound: minecraft:block.anvil.land
    category: MASTER
    volume: 1.0
    pitch: 2.0
    count: 2
    interval-ticks: 5
```

`changed`、`released`、`shrinking`、`low` も同じ項目に対応します。既存区画へ統合し、YAML 項目を重複させないでください。

| 通知 | 既定音 | 動作 |
| --- | --- | --- |
| granted | `minecraft:block.anvil.land` | 要求した走行許可を取得。音高 2、2 回 |
| changed | `minecraft:block.anvil.land` | 大きな変化。音高 2、1 回 |
| released | `minecraft:block.iron_trapdoor.close` | 解放 |
| shrinking | `minecraft:entity.experience_orb.pickup` | 走行中に残存移動 MA が縮み始める |
| low | `minecraft:block.note_block.pling` | 残距離僅少 |

Java Edition の `namespace:path` 識別子を用い、省略時の名前空間は `minecraft` です。独自識別子には利用者側資源一式が必要です。範囲：音量 0..4、音高 0.5..2、回数 1..5、`interval-ticks` 1..200。

STCS 発動設定：

```yaml
ma:
  sound:
    enabled: true
    jump-threshold-meters: 20.0
    cooldown-ms: 1500
    low-remaining-meters: 50.0
```

零は残距離僅少閾値を無効にします。履歴幅により境界上の反復警報を防ぎます。通常の滑らかな延伸では、大変化音を繰り返すべきではありません。遅延通知は旧運転士へ鳴らし続けず、その時点の運転権を再確認します。

### 走行音と制動音

走行音量・音高は速度に応じて変化します。既定では 10 km/h 未満で無音、120 km/h で設定上限に達します。`settings.trackside-running-sound-*` を参照してください。

制動を強めたとき、または N・力行から制動へ移ったときに制動音を鳴らし、完全に制動を抜いたときに緩解音を鳴らします。段階的な制動弱めごとに緩解音は鳴りません。`settings.brake-sound-*` を参照してください。現在、主電動機音は含まれません。

`/st reload` の前に全列車を停止してください。音響だけでなくデータも再読込みします。

## 12. STA 契約と電文

STA は主にサーバー JVM 内の Java 業務を公開します。自動公開される Python TCP/WebSocket RBC ではありません。PCC が既存の HTTP/SSE 監視と制限付き分岐器制御の関門を提供します。

| 契約・データ | 主生成元 | 主利用先 | 意味 |
| --- | --- | --- | --- |
| v2 TELEMETRY_REPORT / 1001 | STF | STCS/購読者 | 物理遠隔測定 |
| v2 TRACK_REPORT / 1002 | STCS | PCC/購読者 | 原観測に結付く図上位置標定 |
| v2 TRAIN_REMOVED / 1003 | 生成元整理 | 登録簿/購読者 | 保持占有消去の許可ではない |
| v2 RailNetworkService | STCS | STF/その他 | 図、進路探索、辺上位置、駅前方探索 |
| v3 ConsistObservation | STF | STCS | 編成車両観測・存続周期 |
| v3 RailwayEvent | STF/STCS | PCC/購読者 | 運転事象 |
| v4 DriverDeskService | STF | STCS | 運転士、運転権、ATP 状態 |
| v4 ShadowAuthorityService | STCS | STF/PCC | 実行不能な MA/EoA と区間 |
| v4 SwitchControl | PCC などの呼出元。STCS 検査、STF 転換 | 呼出元 | 版・状態・位置検査および PENDING |

汎用 v2 電文は三種類ですが、API 全体には別個の状態写し、事象、業務もあります。すべてが三電文の実体というわけではありません。

v2 頭部には version、kind、source、sessionId、sequence、emittedAt、trainId が含まれます。品質状態には VALID、UNLOCATED、STALE、EXPIRED、GRAPH_CHANGED、SOURCE_UNAVAILABLE、SCALE_MISMATCH があります。受信側は識別、順序、品質を無視して座標だけを利用してはいけません。

v4 影方式状態写しは `simulationOnly=true` と `executable=false` を持ちます。走行許可データには経路、EoA の辺・偏倚、残距離、観測来歴が含まれます。区間は `fromMeters/toMeters` を含む場合があり、同じ辺に複数区間が存在できます。一つの区間を辺全体の占有として表示・解釈してはいけません。

先頭車中心は証明済み列車最前部位置ではなく、公称編成長は列車完全性の証明ではなく、遅延時の公称 20 TPS 速度は実時間速度ではありません。これらは ETCS に着想を得た計画内契約であり、**SUBSET-026 の伝送電文でも相互運用仕様でもありません**。

### PCC HTTP 接続口

| 接続口 | 内容 |
| --- | --- |
| `GET /api/v1/graph` | RailGraph |
| `GET /api/v1/trains` | 列車表示状態写し |
| `GET /api/v2/messages` | 遠隔測定状態写し |
| `GET /api/v3/railway-events` | 事象 |
| `GET /api/v4/shadow-ma` | 影方式走行許可・区間 |
| `GET /api/v1/config` | 公開ウェブ設定。制御認証票は含まない |
| `GET /api/v1/events` | SSE |
| `POST /api/v4/switch` | 認証付き分岐器制御 |

接続口の版と JAR の版は別です。表示用状態写しを実行可能な走行許可として再送しないでください。これは接続仕様の概要であり、完全自動生成された SDK・構造定義ではありません。外部利用側は指令送信前に、配備版の正確なデータ形状と契約を検証する必要があります。特に、区間端点が null の場合は旧来の辺全体という意味を保持し、明示端点が区間を限定します。

## 13. データ永続化と障害調査

サーバーディレクトリからの相対経路：

| 経路 | データ |
| --- | --- |
| `plugins/SkyTrainFolia/config.yml`、`plugins/SkyTrainFolia/vehicles/` | 全体・音響・車両諸元設定 |
| `plugins/SkyTrainFolia/trains.yml` | 列車編成、属性、防護状態 |
| `plugins/SkyTrainFolia/savedtrains.yml` | 雛形 |
| `plugins/SkyTrainFolia/switches.yml` | 分岐器登録 |
| `plugins/SkyTrainFolia/infrastructure.yml` | STF 施設・標定 |
| `plugins/SkyTrainFolia/stations.yml`、`plugins/SkyTrainFolia/automatic-signs.yml` | 駅・標識記録 |
| `plugins/STCS/markers.yml` | STCS 標識登録 |
| `plugins/STCS/railgraph.json` | 図状態写し。占有台帳ではない |
| `plugins/STCS/occupancy-ledger.json` | 保持根拠。MA 割当強制のために削除してはならない |
| `plugins/SkyPCC/config.yml` | ウェブ設定・秘密認証情報 |

図は依然として一つの論理図・JSON 書出しで、線区別一ファイルに分割された本番用記憶装置ではありません。線名を理由に線区間の物理接続を切断しないでください。稼働中の図・台帳を直接編集せず、書出し複製を解析してください。

| 症状 | 最初の確認項目 |
| --- | --- |
| auto 表示だが駅動作なし | 運転士、明示解放、防護状態、赤石、標識列との対応、阻止理由 |
| 要求受理だが運転台に走行許可なし | `/stcs ma status` と PCC 理由。受理は割当ではない |
| SWITCH_UNKNOWN | 実体分岐器検証、読込み済み所有領域、登録、位置。図にあるだけでは不足 |
| FLEET_UNCERTAIN / 位置不明保持列車 | 台帳・UUID。配線図に列車がなくても根拠は消えない |
| NO_EXIT_CAPACITY | 全編成の進出側収容長、MA 上限、欠落・誤経路 |
| 並行進路が相互阻止 | 実経路、空間区間、旧保持資源、全編成の新鮮な観測 |
| 里程欠落・誤り | Origin/End 方向、線名付き地上子、側線境界、経路曖昧性。読込み後に再構築 |
| PCC INVALID_REQUEST | 形式・改訂・予期状態・位置・フロントエンドとバックエンドの版。必ずしも認証票ではない |
| PCC 書込み無効 | 有効設定、認証票長、ループバック、生成元、依存関係、正確な拒否理由 |
| PENDING が継続 | 非同期読込み、実体再検証・記録。成功ではない |
| 高速トロッコ不具合 | サーバー適合、領域間移動、他の実体制御・削除。速度上限だけではない |

読込み解除は列車後部の進出完了を意味せず、復元根拠は新鮮な位置ではありません。台帳品質の RECOVERING も車上防護状態 RECOVERING とは別です。

報告には、全拡張機能・サーバー版、時刻、列車名・UUID、設備識別子、再現手順、記録、書出し図、占有診断を含めてください。設定を共有する前に認証票を除去します。

## 14. 受入試験と今後の目標

### 最小回帰試験一覧

1. 四拡張機能が読込み成功し、版・説明・設定が正しい。
2. 毎回の乗車で `drive` を要し、旅客は運転権を継承せず、運転士喪失で非常制動が掛かり、再接続で以前の力行が復元しない。
3. 状態 false で回復へ入り、回復中は力行不能、対象 true は停止を要し、再起動後も状態を保持する。
4. 直線、側線、渡り線、背合せ起点、End 以遠の線路、吊下分岐器標識を試し、線区帰属が局所に留まる。
5. 走行中・停止・読込み解除・再起動後の列車を試し、保持根拠が理由なく消えない。
6. 無人処理、要求・解放、続行、対向競合、並行進路、駅咽喉部の収容長、後部進出を試す。
7. 局所・PCC 転換、競合拒否、未読込み PENDING、実際の線路形状、梃子赤石を試す。
8. 運転士専用 BossBar、EoA 里程、区間色、施設検査、記録展開、四言語、明暗配色を確認する。
9. 許可・大変化・縮小・僅少・解放音、滑らかな延伸時に反復しないこと、旧運転士への遅延音がないことを確認する。
10. 手動列車は自動介入を無視し、解放 + auto で駅処理が有効になることを確認し、spawn/destroy は別々に試す。

オフライン Python 試験台は位相構造、方向、占有、予約、EoA を検査しますが、Bukkit 実体存続周期、Folia 処理割当、通信、実制動は扱いません。これはゲーム回帰試験であり、鉄道認証ではありません。

M0 契約・状態と M1 観測・保持は実装され、利用者試験も行われています。M2 はオンライン影方式 MA と空間資源の改善を含みます。過去の受入結果は回帰試験に代わらず、ATP 使用可能性を証明しません。

次の段階は **車上影方式速度照査曲線**にできます。MA/EoA と車両制動諸元から曲線を表示・記録し、制動は掛けません。介入は検証後に限ります。

実 ATP までに必要な残作業には、全編成包絡・整合、走行許可の識別・確認応答・取消し、通信喪失・凍結・迂回規則、速度制限・制動模型、根拠ある資源解放、故障注入試験があります。

## 15. 開発者向け実装要点

本リポジトリには `SkyTrainFolia`、`STCS`、`STA`、`SkyPCC` の四モジュールがあります。共通コンパイル済みコードは `shared`、開発資料は `doc` にあります。実行版は各モジュールの `plugin.yml` または版指令で確認してください。リポジトリ改名によって拡張機能名は変わりません。

### 運動と Folia 境界

STF の運動模型は、先頭車の速度を後続車へ単純複写するだけでなく、線路座標と編成間隔に基づきます。位置補正、乗客表示の平滑化、表示同期は別々の問題です。これにより無制限の安全速度が成立するわけではなく、曲線、勾配、領域遷移、実体削除は重要な試験項目です。

実体・ブロックに対する物理処理は、Folia の実体・領域所有処理割当を守る必要があります。非同期の図・走行許可計算は状態写しを使います。補助スレッドから任意の Bukkit オブジェクトへ触れる許可ではありません。区画読込み、図の認知、分岐器の実時間物理検証は別状態です。区画が読込み済みというだけで、以前は不明だった分岐器の検証完了を証明しません。

Minecraft の更新は、通常指令・設定コードが不変でも、実体内部、パケット・表示統合、処理割当の前提に影響します。適合境界は新サーバー版ごとに再検討・回帰試験が必要です。抽象層は影響範囲を減らしますが、保守不要にはしません。

### TrainCarts との比較範囲

- 現行の標識作業は station、spawn、destroy を対象とし、前述の STF/SkyTrain 先頭行および解析・作動規則を用います。
- 線路と標識の対応は標識列・取付け模型に従い、TC の全標識動作・式への対応を主張しません。
- STF 分岐器定義は明示的な幾何・接続口・転換器を表します。TC switcher の進路選択式として解釈してはいけません。
- 駅標識の馴染みある画面は、内部制御器の同一性を意味しません。この MVP は車両段位を入力し、最終停止位置合わせを別処理します。
- 行先付帯情報、参考用駅前方探索、資源予約、実行可能な走行許可は別層です。一つがあっても他が完成済みとは限りません。

### 構築と検証の範囲

ソースツリーには `build.ps1` という PowerShell 構築・回帰試験入口があります。`-ServerRoot /path/to/prepared-server` と `-JavaHome /path/to/jdk-25` を渡すか、`JAVA_HOME` を設定します。サーバーの `versions/26.2/shiroha-26.2.jar` と `libraries/` を依存物として読み、まず STA、次に他モジュールを構築して Java 試験を実行します。サーバーを起動、配備、変更しません。依存物は同梱されません。完成 JAR の導入にソースコードの構築は不要です。出力先は版管理対象外の `artifacts/` と `target/` です。`package-source.ps1` は `dist/` にソースコードだけの ZIP を作ります。

自動検査は契約、状態遷移、空間競合・保持、閲覧器描画を扱います。乗車・運転士存続周期、Folia 所有、物理赤石、区画読込み、運動には実サーバー試験が引き続き必要です。文書翻訳は、新たな実行時検証でも新発行版でもありません。

本書は単独で読めるよう作成されています。導入、権限、対応指令形式、設定、運用手引、API 境界、既知の制限を含み、他の README や過去の発行記録を必要としません。
